# Plan 05-03: Driver 层深度优化

**Phase:** 5 — 性能与Bug修复
**Created:** 2026-07-10
**Status:** Not started
**Requirements:** PERF-01, PERF-03

---

## Goal

将 Windows Driver 的 FFI 调用从 9 次（快速路径）降到 6 次以下，修复状态同步风险，为 macOS/Linux 引入乐观更新。

## Context

当前 Driver 层分析：

| Driver | 进入全屏 FFI | 退出全屏 FFI | 同步/异步 | 回调机制 |
|--------|-------------|-------------|-----------|----------|
| Windows (标准) | 11 次 | 7 次 | 同步 | 不需要 |
| Windows (快速) | 9 次 | 5 次 | 同步 | 不需要 |
| macOS | N/A (插件) | N/A (插件) | 异步 | NSWindowDelegate |
| Linux | N/A (插件) | N/A (插件) | 异步 | GdkWindow 信号 |
| 通用 (fallback) | N/A (wm) | N/A (wm) | 异步 | 不需要 |

核心瓶颈：Windows FFI 调用次数 × 每次调用的开销。

---

## Tasks

### T1: 缓存显示器信息（P0）

**目标：** 消除每次全屏时的 `monitorFromWindow` + `getMonitorRect` 重复查询。

**当前：** 每次 enterFullscreen 都调用 2 次 FFI 查显示器信息。
**优化：** 缓存显示器 rect，仅在 `WM_DISPLAYCHANGE` 时刷新。

```
文件: lib/kernel/bridge/platform/windows_fullscreen_driver.dart
改动:
  - 新增 _cachedMonitorRects Map<int, Rect> 缓存
  - monitorFromWindow + getMonitorRect 结果写入缓存
  - 新增 onDisplayChange() 方法清空缓存
  - WindowService 监听 WM_DISPLAYCHANGE 转发
收益: 进入全屏 9→7 次 FFI，退出全屏 5→4 次
```

### T2: 合并退出全屏的位置更新（P0）

**目标：** 消除 `leaveFullscreenFast` 中 `setWindowPlacement` + `setWindowPos` 的冗余调用。

**当前：** `setWindowPlacement` 已触发 `WM_PAINT` 布局刷新，随后的 `setWindowPos(SWP_FRAMECHANGED)` 重复刷新。
**优化：** 在 `leaveFullscreenFast` 中去掉第二次 `setWindowPos`，`setWindowPlacement` 的 `SWP_FRAMECHANGED` flag 已足够。

```
文件: lib/kernel/bridge/platform/windows_fullscreen_driver.dart
改动:
  - leaveFullscreenFast(): 去掉 setWindowPos 刷新调用
  - 保留 setWindowPlacement（它本身带 SWP_FRAMECHANGED）
收益: 退出全屏 5→4 次 FFI（配合 T1 从 5→3）
```

### T3: 修复 `_isFullscreen` 状态同步风险（P0）

**目标：** 防止外部窗口操作导致 Driver 内部状态与实际不同步。

**问题：** `_isFullscreen` 只在 enter/leave 时更新，如果用户通过 Win+↑ 最大化、或 OS 级操作改变了窗口样式，`queryFullscreen()` 返回错误值。

```
文件: lib/kernel/bridge/platform/windows_fullscreen_driver.dart
改动:
  - queryFullscreen(): 每次查询时用 GetWindowLong 验证 WS_THICKFRAME 是否存在
  - 如果实际状态与 _isFullscreen 不一致，自动修正 + debugPrint 警告
  - 保持 _isFullscreen 缓存（避免每次都 FFI），但加验证
收益: 状态一致性保障，零额外性能开销（验证本身也是 FFI 但极轻量）
```

### T4: macOS/Linux 乐观更新（P1）

**目标：** macOS/Linux 进入全屏时 UI 立即响应，不等 700ms 回调。

**问题：** 当前 macOS 进入全屏要等 NSWindowDelegate 回调确认（~700ms），期间 UI 看起来"没反应"。

```
文件: lib/kernel/bridge/desktop_fullscreen_adapter.dart
改动:
  - _handleEnter: 在调用 driver.enterFullscreen() 前就更新 effectiveMode
  - 设置 phase = entering + 立即广播 enterRequested 事件
  - UI 层收到 enterRequested 就开始过渡动画
  - 回调确认后 phase = stable，失败则回滚 + 显示错误
收益: macOS/Linux 用户体感从 700ms→0ms（感知延迟消除）
```

### T5: 工厂运行时降级（P1）

**目标：** Windows Driver 初始化失败时自动降级到通用 Driver。

```
文件: lib/kernel/bridge/desktop_fullscreen_driver_factory.dart
改动:
  - create(): try WindowsFullscreenDriver，探测 HWND 有效性
  - HWND=0 或 FFI 异常 → 降级到 DesktopFullscreenDriver
  - debugPrint 记录降级原因
收益: 健壮性提升，特殊环境下不崩溃
```

### T6: 接口瘦身评估（P3，可选）

**目标：** 评估是否拆分 FullscreenDriver 为核心接口 + 扩展接口。

**当前：** 11 个方法，但 Adapter 高频调用的只有 3-4 个。

```
文件: lib/kernel/bridge/fullscreen_driver.dart
评估:
  - 核心: enterFullscreen, leaveFullscreen, queryFullscreen, onNativeStateChanged
  - 扩展: getPosition, getSize, setBounds, maximize, restore, focus, isMaximized, isMinimized
  - 决定: 是否值得拆分？还是保持现状（接口统一也有好处）
收益: 代码整洁度（如果实施）
```
