    **1. Add `_cachedHwnd` field (after line 73):**

    Add a cached HWND field alongside the existing monitor cache fields:
    ```dart
    /// Cached HWND — stable for Flutter window lifetime (T4).
    ///
    /// getFlutterHwnd() calls FindWindowW which is an FFI round-trip.
    /// Since the Flutter window HWND never changes, cache it on first use.
    /// Cleared on [dispose] and [clearMonitorCache] (defensive).
    int _cachedHwnd = 0;
    ```

    **2. Add `_getHwnd()` helper method (in the internal helpers section, after `_getDevicePixelRatio`):**

    Private helper that returns cached HWND or fetches+stores on first call:
    ```dart
    /// Get cached HWND — fetches once via getFlutterHwnd, then returns cache.
    ///
    /// Returns 0 if window handle is invalid (FindWindowW failed).
    int _getHwnd() {
      if (_cachedHwnd != 0) return _cachedHwnd;
      _cachedHwnd = _api.getFlutterHwnd();
      return _cachedHwnd;
    }
    ```

    **3. Update `enterFullscreenFast()` (line 182):**

    Replace `final hwnd = _api.getFlutterHwnd();` with `final hwnd = _getHwnd();`. This saves 1 FFI call on subsequent fullscreen toggles (first call still invokes FindWindowW, subsequent calls return cached value).

    **4. Update `leaveFullscreenFast()` (line 243):**

    Same replacement: `final hwnd = _api.getFlutterHwnd();` becomes `final hwnd = _getHwnd();`.

    **5. Update `dispose()` (line 356):**

    Add `_cachedHwnd = 0;` to clear the cached HWND when the driver is disposed.

    **6. Update `clearMonitorCache()` (line 366):**

    Add `_cachedHwnd = 0;` as a defensive clear. When monitors change, the HWND could theoretically be recreated (edge case: window moved to different virtual desktop on some Windows configurations).

    **7. Do NOT change `enterFullscreen()`, `leaveFullscreen()`, `queryFullscreen()`, or other methods.**

    These standard-path methods should continue calling `_api.getFlutterHwnd()` directly. The standard path already has diagnostic verification overhead; caching there is not worth the risk of stale HWND in defensive code paths. Only the fast paths (which skip diagnostics) benefit from caching.
