**文件 1: `test/helpers/fake_mdk_player.dart` — 纯 Dart mdk.Player 测试替身**

创建 FakeMdkPlayer 实现 mdk.Player 的关键方法子集。mdk.Player 是 FFI 类，无法直接 mock，需要提取测试用接口。

FakeMdkPlayer 需要模拟的方法（通过审计 fvp_engine + media_opener + track_manager 调用链确定）：
- `set media` / `get media` — 设置媒体路径
- `prepare({bool sync})` → 同步模式返回 true（模拟成功）
- `start()` → 改变内部状态
- `stop()` → 改变内部状态
- `get state` → 返回 MediaState 枚举值
- `set state(callback)` — 状态回调注册
- `set volume` / `get volume`
- `set mute` / `get mute`
- `seekTo(position, {callback})` → 回调成功
- `setVideoSurfaceSize({width, height, ...})`
- `setProperty(key, value)` / `getProperty(key)`
- `get videoHeight` / `get videoWidth` / `get videoRotation`
- `get audioTracks` / `get subtitleTracks`
- `setActiveTrack(type, index)`
- `setExternalSubtitle(path, ...)`
- `get buffered` — 返回 0
- `dispose()` — 清理

关键设计：
- 使用 `typedef PlayerFactory = mdk.Player Function()` 作为工厂类型
- FakeMdkPlayer 不 import `package:fvp/mdk.dart`（避免 FFI）
- 用 `dynamic` 类型或创建一个 `FakePlayer` 类，让 FvpEngine 的 factory 参数类型为 `dynamic Function()` 或提取接口

实际实现策略（最简方案）：
- 在 `player_proxy.dart` 中不改动（已有的 PlayerProxy 接口仅覆盖 volume/mute/setProperty/getProperty）
- FvpEngine 的 `playerFactory` 参数类型为 `dynamic Function()`，默认 `() => mdk.Player()`
- FakeMdkPlayer 用 dynamic 返回，所有 mdk.Player 方法通过 noSuchMethod 或具体实现模拟
- 这样不需要修改 mdk 包本身

更安全的方案：
- 定义 `MdkPlayerLike` 抽象接口（在 player_proxy.dart 中扩展），包含 MediaOpener/TrackManager 需要的方法
- FvpEngine 接受 `MdkPlayerLike Function()` 工厂
- `MdkPlayerProxy` 已存在的部分方法 + 需要扩展

推荐采用"更安全方案"：在 `player_proxy.dart` 中扩展 PlayerProxy 接口为 `MdkPlayerLike`，包含 open/prepare/state/seek/track 方法。FvpEngine factory 接受 `MdkPlayerLike Function()`。`MdkPlayerProxy` 实现此接口包装 `mdk.Player`。

**文件 2: 修改 `lib/kernel/engine/fvp_engine.dart`**

在工厂构造函数中添加 `playerFactory` 参数：
- 类型: `mdk.Player Function()` 或 `MdkPlayerLike Function()`（取决于接口方案）
- 默认值: `() => mdk.Player()`
- 将 `final player = mdk.Player()` 改为 `final player = playerFactory()`
- 所有 helper（MediaOpener, TrackManager, VideoEffectController, FvpCallbackHandler, PositionPoller）的 mdk.Player 参数不变（它们已经在使用 player 实例）

注意：如果采用 MdkPlayerLike 接口方案，需要同步修改 MediaOpener/TrackManager/VideoEffectController 的构造函数参数类型从 `mdk.Player` 改为 `MdkPlayerLike`。这会增加改动范围但提升可测试性。

如果改动范围过大（>5 个文件），简化为 `dynamic Function()` 方案，仅改 FvpEngine 一个文件。
