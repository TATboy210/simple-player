**Step 5: Pass onReset callbacks to tabs in _buildTab**

Update `_buildTab` to pass `onReset` callback to each tab:
- GeneralTab: `onReset: () => _resetTab(0)` — but since GeneralTab is StatelessWidget and reset is handled by SettingsPanel pending values, the callback just triggers `_resetTab(0)`.
- EqualizerTab: `onReset: () => _resetTab(1)` — BUT also need to reset `_selectedIndex`. Since EqualizerTab is StatefulWidget, the callback must be wrapped so EqualizerTab can reset its internal state AND call the engine reset. Solution: EqualizerTab's `onReset` callback is called by the tab widget, and inside the tab it resets `_selectedIndex` and calls `widget.engine.setEqualizer('')`. The SettingsPanel only shows the dialog — the actual reset logic is in the tab. See Task 2 for tab-side changes.
- VideoTab: `onReset: () => _resetTab(3)` — VideoTab calls `service.resetAll()` internally.
- ShortcutsTab: `onReset: () => _resetTab(4)` — ShortcutsTab clears `_customBindings` internally.
- PerformanceTab: `onReset: () => _resetTab(6)` — PerformanceTab resets notifiers internally.

**Revised architecture:** The `onReset` callback pattern works as follows:
1. SettingsPanel provides the callback (shows confirmation dialog)
2. If confirmed, the callback calls the tab's reset logic
3. The tab handles its own internal state reset

For tabs with internal state (EqualizerTab, ShortcutsTab, PerformanceTab):
- The `onReset` callback shows the dialog
- If confirmed, the tab's own reset method runs (resets internal state + persists)

For tabs without internal state (GeneralTab, VideoTab):
- The `onReset` callback shows the dialog
- If confirmed, SettingsPanel's `_resetTab` handles everything

Implementation approach: Use a two-callback pattern:
- `onResetRequest: VoidCallback` — tab calls this to request reset (triggers dialog)
- The tab wraps its reset button with `onResetRequest` which shows dialog, and if confirmed, the tab runs its own reset logic

Actually, simpler: Use a single `VoidCallback onReset` that the tab calls. The callback shows the dialog. If confirmed, it returns `true` (via a `Future<bool>`). The tab checks the return value and executes reset if true.

Revised callback signature: `final Future<bool> Function()? onResetRequest` — returns true if user confirmed.

OR even simpler: Keep the confirmation dialog in SettingsPanel, but have the callback chain work like this:
1. Tab's reset button calls `widget.onResetRequest?.call()`
2. `onResetRequest` shows the dialog
3. If confirmed, executes `_resetTab(index)` which handles all reset logic (both SettingsPanel-level and tab-level)

For tab-level resets, `_resetTab` uses `setState` to update SettingsPanel state (General pending values), calls engine/service methods directly (EQ, Video, Shortcuts), and for PerformanceTab, recreates the notifiers.

This is the cleanest approach. `_resetTab` is the single source of truth for all reset logic.

For EqualizerTab: `_resetTab(1)` calls `widget.engine.setEqualizer('')` AND the tab needs to know to reset `_selectedIndex`. Solution: EqualizerTab listens to the engine's equalizer value, OR use a `ValueNotifier<int>` for the selected index that SettingsPanel controls, OR simply rebuild the tab with a new key after reset (which resets all state).

**Final decision: Rebuild tab with new key after reset.**

After `_resetTab` executes the reset logic, call `setState` which rebuilds `_buildTab(_selectedIndex)`. For EqualizerTab, the `_selectedIndex` starts at 0 in `initState`, so if we force a rebuild with a new Key, the state resets. We can use `ValueKey(DateTime.now().millisecondsSinceEpoch)` to force rebuild.

But this is fragile. Better approach: Add an `initialSelectedIndex` parameter to EqualizerTab that SettingsPanel controls. When reset happens, SettingsPanel sets it to 0 and the tab uses it.

Actually, the simplest approach: EqualizerTab is already rebuilt when `setState` is called in SettingsPanel (because `_buildTab` is called in `build`). But EqualizerTab is StatefulWidget, so its state persists across parent rebuilds unless the Key changes.

**Use a reset counter:**
Add `int _eqResetCounter = 0` to SettingsPanel. After resetting EQ, increment it. Pass it as part of the Key: `ValueKey('eq-$_eqResetCounter')`. This forces EqualizerTab to recreate, resetting `_selectedIndex` to 0.

Same for ShortcutsTab (`_shortcutsResetCounter`) and PerformanceTab (`_perfResetCounter`).

This is clean and works with the existing StatefulWidget pattern.
