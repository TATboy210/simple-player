  <action>
Refactor WindowService FFI bindings to lazy initialization so test imports do not crash.

**Step 1 — FFI guard in `window_service.dart`:**
The top-level FFI lookup calls (`_getWindowLongPtr`, `_setWindowLongPtr`, etc.) execute at import time and crash in the Flutter test environment which has no Win32 user32.dll. Wrap all FFI bindings in a lazy singleton pattern:

- Change the 6 top-level FFI `_lookupFunction` calls and the `_dwmapi` lookup to use `late final` with an `_initFfi()` function guarded by `bool _ffiInitialized = false`.
- Create a class `_Win32Bindings` (private, file-scoped) that holds all the FFI function references as `late final` fields. Its `init()` method performs the actual `DynamicLibrary.open` + `lookupFunction` calls.
- Expose a single `late final _Win32Bindings _win32` that initializes on first access.
- All existing references (`_getWindowLongPtr`, `_setWindowLongPtr`, etc.) become getters that delegate to `_win32.fieldName`.
- The `_removeBorder()` and `_enterFullscreen()`/`_exitFullscreen()` methods already run asynchronously, so the lazy init is transparent to them.

This is a pure refactor — no behavioral change. The FFI calls only execute when `WindowService` methods are actually invoked, not at import time.

**Step 2 — Create `test/helpers/fake_window_service.dart`:**
Now that importing `window_service.dart` is safe, create a `FakeWindowService` that extends `WindowService`:

- Override `init()` to be a no-op (skip `windowManager.addListener` and `_removeBorder`).
- Override `setFullscreen(bool)` to toggle `isFullscreen.value` directly (no FFI).
- Override `setAlwaysOnTop(bool)` to toggle `isAlwaysOnTop.value` directly.
- Override `setSize`, `setMinSize`, `minimize`, `maximize`, `restore`, `close`, `center`, `startDragging` as no-ops.
- Override `dispose()` to only dispose ValueNotifiers (skip `windowManager.removeListener`).
- Add call tracking: `int fullscreenCallCount`, `bool? lastFullscreenValue` for test assertions.

**Step 3 — Create `test/helpers/integration_helpers.dart`:**
Reusable test harness for integration tests:

- `Widget buildTestApp({required MediaEngine engine, required Widget child})` — wraps child in `MaterialApp` with `AppLocalizations.localizationsDelegates` and `Scaffold`.
- `PlaybackController createTestController(FakeEngine engine)` — creates a `Playlist` + `PlaybackController` wired to the engine with a no-op `onNeedRebuild`.
- `FakeWindowService createFakeWindowService()` — factory with sensible defaults.

  <action>
Write three integration test files covering all TEST-05 flows. Each file uses `FakeEngine` + `FakeWindowService` + `createTestController` from the harness.

**File 1: `integration_test/playback_flow_test.dart`**
Tests the core playback lifecycle. Each test builds a `PlayerScreen` (or `ControlBar` + `ProgressBar` combo) with a pre-configured `FakeEngine`:

- `testWidgets('open file starts playback')` — Call `controller.openAndPlay('test.mp4')`, assert `engine.state.value == MediaState.playing`, `engine.openCallCount == 1`.
- `testWidgets('seek updates position')` — Set `engine.duration.value = 60000`, simulate seek via `engine.seekTo(30000)`, assert `engine.position.value == 30000`, `engine.seekToCallCount == 1`.
- `testWidgets('pause stops playback')` — Open a file, then call `engine.pause()`, assert `engine.state.value == MediaState.paused`, `engine.pauseCallCount == 1`.
- `testWidgets('togglePlayPause cycles states')` — Start playing, toggle, assert paused. Toggle again, assert playing.
- `testWidgets('skip forward advances position')` — Set position=10000, duration=60000, call `engine.skipForward(10)`, assert position=20000.
- `testWidgets('skip back decreases position')` — Set position=30000, call `engine.skipBack(10)`, assert position=20000.

**File 2: `integration_test/controls_flow_test.dart`**
Tests volume, mute, and fullscreen controls:

- `testWidgets('setVolume changes volume')` — Call `engine.setVolume(0.5)`, assert `engine.volume.value == 0.5`.
- `testWidgets('setVolume clamps to 0-1')` — Call `engine.setVolume(1.5)`, assert `== 1.0`. Call `engine.setVolume(-0.5)`, assert `== 0.0`.
- `testWidgets('setMute toggles mute state')` — Call `engine.setMute(true)`, assert `engine.isMuted.value == true`.
- `testWidgets('volume 0 sets muted')` — Call `engine.setVolume(0)`, assert `engine.isMuted.value == true`.
- `testWidgets('fullscreen toggle updates state')` — Use `FakeWindowService`, call `setFullscreen(true)`, assert `isFullscreen.value == true`, `fullscreenCallCount == 1`.
- `testWidgets('playback speed changes')` — Call `engine.setPlaybackRate(2.0)`, assert `engine.playbackSpeed.value == 2.0`.

**File 3: `integration_test/playlist_flow_test.dart`**
Tests playlist navigation and play modes:

- `testWidgets('playNext advances to next track')` — Add 3 items to playlist, set currentIndex=0, call `controller.playNext()`, assert `playlist.currentIndex == 1`, `engine.openCallCount == 2` (first open + next).
- `testWidgets('playPrevious goes back')` — Start at index 2, call `controller.playPrevious()`, assert `playlist.currentIndex == 1`.
- `testWidgets('playNext wraps at end in loopAll')` — Set mode=loopAll, start at last index, call `playNext()`, assert wraps to index 0.
- `testWidgets('loopSingle replays same track')` — Set mode=loopSingle, call `playNext()`, assert same index.
- `testWidgets('cycle play modes')` — Toggle mode from loopAll to loopSingle to shuffle, assert `playlist.mode` changes correctly.
- `testWidgets('addFiles adds to playlist')` — Call `controller.addFiles(['a.mp4', 'b.mp4'])`, assert `playlist.length == 2`.

For each test, configure `FakeEngine` with `configureMedia(durationMs: 60000)` before opening. Use `tester.pumpAndSettle()` after async operations. Build only the component under test (not full PlayerScreen when not needed) to avoid WindowService FFI issues — use ControlBar + ProgressBar for playback tests, and direct PlaybackController/Playlist calls for navigation tests.
