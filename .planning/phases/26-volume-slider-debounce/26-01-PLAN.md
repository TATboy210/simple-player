# Phase 26: VolumeSlider Debounce

## Problem Statement

VolumeSlider 拖拽时，每个 pointer move 事件（~60/sec）同步触发：
1. `engine.setVolume(v)` → FFI 调用 `_player.volume = v`（MDK 跨线程）
2. `OsdService.I.show(...)` → 设置 ValueNotifier 触发 OSD widget rebuild

**当前频率**: ~60 次/秒（每个像素移动一次）
**目标频率**: ≤10 次/秒（100ms 间隔）

## Current Call Chain

```
Slider.onChanged(v) [every pointer move]
  → engine.setVolume(v)
    → VolumeController.setVolume(v)
      → _player.volume = v  (FFI to MDK)
      → volume.value = v    (ValueNotifier)
  → OsdService.I.show(...)
    → message.value = ...   (triggers rebuild)
```

## Solution Design

### Approach: Widget-level throttle + onChangeEnd flush

Convert `VolumeSlider` from `StatelessWidget` to `StatefulWidget`:

1. **Add `_volumeThrottle` Timer** — 100ms interval, same pattern as `ProgressBar._seekThrottle`
2. **Add `_pendingVolume` field** — store latest value during throttle window
3. **In `onChanged`**: update `_pendingVolume`, only start timer if not already running
4. **In timer callback**: fire `engine.setVolume(_pendingVolume)` + OSD show
5. **Add `onChangeEnd`**: cancel timer, immediately flush final value (zero perceived latency)
6. **Pointer scroll** stays unthrottled — discrete events, not continuous drag

### Token Addition

```dart
// In tokens.dart
static const int volumeThrottleMs = 100;  // ≤10 calls/sec during drag
```

## Risk Assessment

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| Throttle makes drag feel laggy | Low | 100ms is imperceptible; onChangeEnd provides instant final sync |
| Timer leak on rapid widget dispose | Low | Standard `dispose()` → `cancel()` pattern, proven in ProgressBar |
| Race between throttle and ValueListenableBuilder | Low | Slider value is bound to `engine.volume` notifier; throttle only delays the engine call, not the visual position |

## 详细代码规划（逐行解释）

### 问题的生活类比

想象你在拧水龙头调节水量：

**现在的做法（问题）**：
- 手每移动 1 毫米 → 立刻通知水厂"我要这个水量！" → 水厂调整水泵 → 大屏幕更新
- 每秒重复 60 次 → 水厂被疯狂通知，大屏幕疯狂闪烁，但最终水量还没定

**正确的做法（修复后）**：
- 手移动 → 记住"我要这个水量"，先不通知水厂
- 每 0.1 秒才通知一次水厂（用最新值）
- 手松开 → 立刻通知水厂"最终水量是这个！"

#### 第 119-125 行：鼠标滚轮处理（不改动）

```dart
onPointerSignal: (event) {
  if (event is PointerScrollEvent) {
    final delta = event.scrollDelta.dy > 0 ? -0.05 : 0.05;
    // ↑ 滚轮向上 = 音量 -5%，向下 = 音量 +5%
    final v = (engine.volume.value + delta).clamp(0.0, 1.0);
```

滚轮是**离散事件**（每秒 3-5 次），不需要节流，保持原样。

#### 第 131-136 行：拖动处理（问题所在）

```dart
child: Slider(
  value: volume,                     // 滑块当前位置 = 引擎当前音量
  onChanged: (v) {                   // ★★★ 当用户拖动滑块时...
    engine.setVolume(v);             // ★ 每拖 1 个像素就通知引擎！（60次/秒）
    OsdService.I.show('${(v * 100).round()}%', progress: v);
    // ★ 每拖 1 个像素就弹一次提示！（60次/秒）
  },

),
```

**问题**：`onChanged` 里的两行代码，每次手指移动 1 个像素都执行。
手指移动 1 秒 = 执行 60 次 = 引擎被调用 60 次 + OSD 刷新 60 次。

### 修复方案逐行详解

#### 改动 1：从"无记忆"变成"有记忆"

```dart
// 改前：无状态（不记住任何东西）
class VolumeSlider extends StatelessWidget {

// 改后：有状态（能记住定时器和待提交的值）
class VolumeSlider extends StatefulWidget {
  @override
  State<VolumeSlider> createState() => _VolumeSliderState();
}
```

类比：
- `StatelessWidget` = 一张白纸，每次都要重新画
- `StatefulWidget` = 一本笔记本，可以翻到之前记的页

为什么需要：我们要记住"定时器还在不在"和"最新的音量值是多少"。

#### 改动 2：新增"笔记本"（State 类）

```dart
class _VolumeSliderState extends State<VolumeSlider> {

  Timer? _throttleTimer;    // 节流定时器（null = 没有定时器在跑）
  double? _pendingVolume;   // 待提交的音量值（null = 没有待提交的值）
```

这两个变量就是"笔记本上记的东西"。

#### 改动 3：新增"拖动时的处理"（_onChanged）

```dart
void _onChanged(double v) {
  _pendingVolume = v;         // 1. 把最新音量记在笔记本上
  _throttleTimer ??= Timer(   // 2. 如果没有定时器在跑，就启动一个
    const Duration(milliseconds: Tokens.volumeThrottleMs),  // 100 毫秒后触发
    _flushPending,             // 3. 触发时执行 _flushPending
  );
}
```

逐行解释：

| 代码 | 在做什么 | 类比 |
|------|---------|------|
| `_pendingVolume = v` | 记住最新的音量值 | 在纸上写"我要 75%" |
| `_throttleTimer ??=` | `??=` 意思是"如果是 null 就赋值" | "如果没在倒计时，就开始倒计时" |
| `Timer(Duration(...), _flushPending)` | 100 毫秒后自动执行 `_flushPending` | 设一个 0.1 秒的闹钟 |

关键：`??=` 保证 100 毫秒内只创建**一个**定时器。后续的拖动事件只更新 `_pendingVolume`，不会创建新定时器。

#### 改动 4：新增"定时器到期时的处理"（_flushPending）

```dart
void _flushPending() {
  _throttleTimer = null;       // 1. 定时器用完了，清空它
  final v = _pendingVolume;    // 2. 取出最新音量
  if (v == null) return;       // 3. 如果没有待提交的值，就不做事
  widget.engine.setVolume(v);  // 4. ★ 通知引擎："把音量改成 v"
  OsdService.I.show('${(v * 100).round()}%', progress: v);
  // 5. ★ 在屏幕上弹出提示："音量 75%"
}
```

这就是"批量提交"：100 毫秒内不管拖了多少次，只通知引擎一次（用最新的值）。

#### 改动 5：新增"松手时的处理"（_onChangedEnd）

```dart
void _onChangedEnd(double v) {
  _throttleTimer?.cancel();    // 1. 取消还在跑的定时器（如果有）
  _throttleTimer = null;       // 2. 清空定时器
  _pendingVolume = null;       // 3. 清空待提交值
  widget.engine.setVolume(v);  // 4. ★ 立刻通知引擎最终音量！（零延迟）
  OsdService.I.show('${(v * 100).round()}%', progress: v);
  // 5. ★ 立刻弹出最终提示
}
```

为什么需要：用户松手的那一刻，音量应该**立刻**到达最终值，不用再等 100 毫秒。

#### 改动 6：新增"清理"（dispose）

```dart
@override
void dispose() {
  _throttleTimer?.cancel();    // 组件销毁时，取消定时器
  super.dispose();
}
```

为什么需要：如果用户在拖动时突然关闭了播放器页面，定时器还在跑就会出错。这叫"防止内存泄漏"。

#### 改动 7：build 方法中的 3 处小改

```dart
// 改动 A：engine → widget.engine
// 原因：StatelessWidget 中直接用 engine，StatefulWidget 中要用 widget.engine
widget.engine.setVolume(v);     // 原来是 engine.setVolume(v)

// 改动 B：onChanged 从"直接调用"改为"调用 _onChanged"
onChanged: (v) => _onChanged(v),    // 原来是直接写 engine.setVolume(v) + OsdService...

// 改动 C：新增 onChangeEnd
onChangeEnd: (v) => _onChangedEnd(v),  // 原来没有这行
```

### 时间线：一次完整拖动过程

```
时间 (毫秒)   事件                    代码行为
─────────────────────────────────────────────────────────
0ms         手指按下滑块            （无操作）
20ms        手指拖到 50%            _onChanged(0.5)
                                    → _pendingVolume = 0.5
                                    → 创建定时器（100ms 后触发）
40ms        手指拖到 60%            _onChanged(0.6)
                                    → _pendingVolume = 0.6（更新）
                                    → 定时器已在跑，不创建新的
60ms        手指拖到 70%            _onChanged(0.7)
                                    → _pendingVolume = 0.7（更新）
80ms        手指拖到 80%            _onChanged(0.8)
                                    → _pendingVolume = 0.8（更新）
100ms       定时器到期！             _flushPending()
                                    → engine.setVolume(0.8)  ← 第一次通知引擎
                                    → OSD 显示 "80%"
120ms       手指拖到 90%            _onChanged(0.9)
                                    → _pendingVolume = 0.9
                                    → 创建新定时器
150ms       手指松开！              _onChangedEnd(1.0)
                                    → 取消定时器
                                    → engine.setVolume(1.0)  ← 立刻通知最终值
                                    → OSD 显示 "100%"

结果：从 60 次/秒 → 最多 10 次/秒 + 松手时 1 次即时同步
```

### 已有代码参照：ProgressBar 的相同模式

