**PerfMonitor cleanup (CONCERNS #14, #15):**

1. Remove `mark(String label)` and `markEnd(String label)` methods (lines 96-103) — dead code with zero callers in the codebase (CONCERNS #15).

2. Replace unbounded `_buildTimes` and `_rasterTimes` lists with a fixed-capacity circular buffer (CONCERNS #14). Current behavior: lists grow to 1000 then `clear()` entirely, causing periodic memory spikes. Target: use a fixed-capacity approach with `_maxFrames = 300` constant. When buffer is full, overwrite oldest entry (ring buffer index = `_currentIndex % _maxFrames`). Keep the `_printStats()` method but adapt it to read from the circular buffer. Keep the 100-frame reporting interval.

3. In `_printStats()`, replace `_buildTimes.clear(); _rasterTimes.clear();` with resetting the write index. The circular buffer naturally overwrites old data, so no explicit clearing needed.

4. Update `exportStats()` to work with the circular buffer (read up to `_maxFrames` entries).

5. In `enable()`/`disable()`, no changes needed (already correct).

**queryFence automation (D-32, D-21):**

Create `scripts/apply_queryfence_patch.dart` — a Dart script that:
1. Locates the fvp package in the pub cache (check `.dart_tool/package_config.json` for fvp path)
2. Checks if the queryFence patch has already been applied (grep for a marker string or check if the patched file differs from the original)
3. If not applied, copies the patch file from the project to the fvp pub cache location
4. Prints a summary of what was done (applied/skipped/error)

The script should be runnable via `dart run scripts/apply_queryfence_patch.dart` and return exit code 0 on success, 1 on error.

Note: The actual patch content is data-driven. The script should look for a patch file at `patches/fvp_queryfence.patch` in the project root. If the patch file doesn't exist, the script should print a warning and exit 0 (non-fatal). This is the automation skeleton — the actual patch content will be added after D3D11 parameter research confirms the specific changes needed.
