**Error handling re-scan (D-30):**

Scan the entire `lib/` directory for error handling anti-patterns. The Phase 1 fix (PERF-02) addressed playlist_store.dart:168, engine_prewarm.dart:56, and subtitle_service.dart:37,59. This task checks if those fixes are still in place and finds any NEW anti-patterns.

**1. Scan for `catch (_)` pattern:**
Search all `.dart` files in `lib/` for `catch (_)` — this silently swallows ALL exceptions including Error subtypes. Every instance should be `on Exception catch (e)` with `debugPrint` logging.

**2. Scan for `on Object catch` pattern:**
Search for `on Object catch` — this catches Error subtypes (TypeError, RangeError) that should propagate. Change to `on Exception catch (e)`.

**3. Fix CONCERNS #18 — FvpEngine.subtitleDelay:**
At `fvp_engine.dart:544`, the `subtitleDelay` getter catches silently:
```dart
} catch (e) {
  log.d('FvpEngine.subtitleDelay parse error: $e');
  return 0;
}
```
This already has logging via `log.d`. Verify it uses `on Exception catch (e)` (not bare `catch (e)`). If it's bare `catch`, change to `on Exception catch (e)`.

**4. Fix any new anti-patterns found:**
For each instance found:
- Change `catch (_)` to `on Exception catch (e)` + `debugPrint('ComponentName.method error: $e')`
- Change `on Object catch` to `on Exception catch (e)`
- If the catch block has meaningful recovery logic, preserve it
- If the catch block is empty or just `// skip`, add `debugPrint` logging

**5. Update CONCERNS.md:**
Mark CONCERNS #3, #4, #18 as resolved (or verify they were resolved in Phase 1). Add any new findings.
