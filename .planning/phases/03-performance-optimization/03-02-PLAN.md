**Root cause analysis (per D-09, D-10):**

Based on profiling data from Task 1, apply targeted fixes. The likely root causes (in priority order) are:

**Possible cause A: BackdropFilter GPU readback overhead**
- Symptom: High raster time when control bar is visible
- Fix: Ensure GlassContainer/ControlBar BackdropFilter is skipped when opacity < 0.01. Verify the existing AnimatedBuilder pattern is correctly gating the BackdropFilter. If the opacity animation never reaches exactly 0 (CurvedAnimation may stop at 0.001), adjust the threshold check.
- Additional: Consider adding a `RepaintBoundary` around the BackdropFilter content if not already present (check existing code — ControlBar already uses `RepaintBoundary(child: content)` at line 121).

**Possible cause B: ValueNotifier rebuild cascade**
- Symptom: High build time when position updates (250ms interval from PositionPoller)
- Fix: The ControlBar rebuilds on every position change because it receives `engine` (MediaEngine) and uses `TimeRangeDisplay` and `ProgressBar` which listen to position/duration. These are already optimized via MergedListenable (Phase 2 audit confirmed). If profiling shows excessive rebuilds, add `RepaintBoundary` between the progress bar row and the button row in ControlBar's Column.

**Possible cause C: Multiple BackdropFilter layers**
- Symptom: ControlBar has its own BackdropFilter AND GlassContainer may add another
- Fix: ControlBar already handles BackdropFilter directly (lines 121-141). Verify no GlassContainer inside ControlBar also applies BackdropFilter. The `_LeftButtonGroup` and `_RightButtonGroup` use `GlassButton.iconOnly` which does NOT use BackdropFilter (confirmed in Phase 2 — icon-only path uses SizedBox + Material + InkWell). So no double-BackdropFilter issue.

**Possible cause D: AnimatedBuilder rebuild overhead**
- Symptom: AnimatedBuilder on opacity triggers rebuilds during fade animation
- Fix: AnimatedBuilder is the correct pattern (lighter than ValueListenableBuilder for animations). If profiling shows this is a bottleneck, consider using `FadeTransition` instead of `AnimatedBuilder` for the opacity gating — but `FadeTransition` doesn't skip the child when opacity is 0. Keep AnimatedBuilder for the skip behavior.

**Apply fixes based on profiling data (D-09: comprehensive):**

After identifying the actual bottleneck(s) from Task 1 profiling:

1. If BackdropFilter is the bottleneck:
   - Verify opacity threshold (0.01) is correct for CurvedAnimation behavior
   - Add `_blurFilter` caching if not already static (it IS static — `_blurFilter` is `static final` at line 17)

2. If ValueNotifier rebuilds are the bottleneck:
   - Add `RepaintBoundary` between progress bar row and button row in ControlBar Column
   - Consider extracting the progress bar row into a separate widget with its own RepaintBoundary

3. If ControlsOverlay rebuilds are the bottleneck:
   - Verify the `child` parameter of `ValueListenableBuilder<bool>` on `_autoHide.visible` is caching the Stack correctly (line 155-217 — the `child` IS cached)
   - Check if `isIdle` changes cause unnecessary rebuilds

4. If progress bar seek is the bottleneck:
   - Profile ProgressBar separately (D-04: "progress bar seek separately")
   - ProgressBar uses MergedListenable (position+duration+buffered+drag) — already optimized
