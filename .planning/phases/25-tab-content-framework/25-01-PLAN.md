**Step 1: Create PendingSettingsState (lib/ui/dialogs/settings/pending_settings.dart)**

Create a plain Dart class (NOT ChangeNotifier, NOT ValueNotifier — per pitfall avoidance rule to prevent IndexedStack cascade rebuilds):

- `_pending` map: `Map<String, dynamic>` holding pending values keyed by setting ID string
- `_originals` map: `Map<String, dynamic>` holding original snapshot values
- `register(String key, dynamic originalValue)`: stores original value in `_originals` (called when panel opens)
- `update(String key, dynamic value)`: stores pending value in `_pending` (called when user changes a setting)
- `current(String key)`: returns `_pending[key] ?? _originals[key]` (display value)
- `hasChanges` getter: `_pending.isNotEmpty`
- `commit()`: returns `Map<String, dynamic>` of pending changes, clears `_pending`, updates `_originals` with committed values (so Apply-then-Cancel uses committed values as new baseline — per Pitfall 3 from RESEARCH)
- `cancel()`: returns `Map<String, dynamic>` of originals, clears `_pending` (tabs re-read `current()` to restore)
- `dispose()`: clears both maps

Add doc comments in Chinese intent + English contract style per DOC-01/DOC-02.

**Step 4: Integrate PendingSettingsState into SettingsPanelController**

Modify SettingsPanelController to own a PendingSettingsState instance:
