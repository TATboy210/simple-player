  <action>
Flesh out `kernel_logger.dart` (~130 lines) by adding the following types ABOVE the existing `abstract class KernelLogger`:

1. `enum LogLevel { trace, debug, info, warn, error, fatal }` — 6 levels per D14, 1:1 with KernelLogger methods.

2. `abstract interface class LogSink` — single method per D4: `void log(LogLevel level, String msg, {Map<String, Object?>? context})`.

3. `final class DevToolsSink implements LogSink` — calls `dart:developer.log(name: 'Kernel', level: _toSeverity(level), msg: _redactPath(msg), time: DateTime.now())` per D15. Map LogLevel to severity int: trace=300, debug=500, info=800, warn=900, error=1000, fatal=1200. Context map NOT passed to dart:developer.log (DevTools has its own structured view); context is a DebugPrintSink concern. Both DevToolsSink and DebugPrintSink apply `_redactPath()` to the message before output.

4. `final class DebugPrintSink implements LogSink` — calls `debugPrint('${level.name.toUpperCase()}: ${_redactPath(msg)}$contextStr')` per D12/D16. Context formatted as ` {key: val}` appended to message.

   Add a top-level helper function `_redactPath(String msg)` (file-private, outside any class) per D17: strips directory prefixes from file paths in log messages. Pattern: use `RegExp(r'[\w/\\]+[/\\]([\w]+\.dart:\d+)')` to detect `lib/kernel/engine/fvp_engine.dart:259` and replace with the captured group `fvp_engine.dart:259` only. Apply in both DevToolsSink and DebugPrintSink before passing msg to their respective output methods. This prevents local filesystem paths from leaking into DevTools and debugPrint output.

5. `final class NullSink implements LogSink` — const, empty method body per D13. Release builds use this.

6. `final class CompositeSink implements LogSink` — takes `List<LogSink>`, iterates and delegates to each per D12 (both DevTools + debugPrint in debug mode).

7. Modify the existing `abstract class KernelLogger`:
   - Add `context` named parameter to `warn`, `info`, `debug`, `trace` methods: `{Map<String, Object?>? context}`.
   - `error` and `fatal` already have `error:` and `stackTrace:` per Phase 16; add `context` parameter to them too.
   - Add shortcut methods directly on the abstract class: `void t(String m, {Map<String, Object?>? context}) => trace(m, context: context);`, `void d(String m, {Map<String, Object?>? context}) => debug(m, context: context);`, `void i(String m, {Map<String, Object?>? context}) => info(m, context: context);`, `void w(String m, {Map<String, Object?>? context}) => warn(m, context: context);`, `void e(String m, {Map<String, Object?>? context, Object? error, StackTrace? stackTrace}) => this.error(m, context: context, error: error, stackTrace: stackTrace);`, `void f(String m, {Map<String, Object?>? context, Object? error, StackTrace? stackTrace}) => this.fatal(m, context: context, error: error, stackTrace: stackTrace);` per D11.

8. Update the existing `NullKernelLogger` to match the new abstract signatures — add `{Map<String, Object?>? context}` to all 6 methods (`trace`, `debug`, `info`, `warn`, `error`, `fatal`). The method bodies remain empty no-ops. This is required because Dart enforces that concrete implementations match the abstract interface exactly.

9. `final class KernelLoggerImpl implements KernelLogger`:
   - Constructor takes `LogSink _sink`.
   - Static nullable `_instance` field + `I` getter that throws `StateError` if null (NOT `late final` — per RESEARCH anti-pattern).
   - Static `init()` factory: `kDebugMode ? CompositeSink([DebugPrintSink(), DevToolsSink()]) : NullSink()` per D13.
   - All 6 full methods delegate to `_sink.log(LogLevel.x, message, context: context)`.
   - Shortcut methods inherited from abstract class.

Add required imports: `import 'dart:developer' as developer;` and `import 'package:flutter/foundation.dart';` (for `kDebugMode` and `debugPrint`).

Add `///` doc comments per project convention (Chinese intent + English contract). Each new type gets a doc comment explaining its purpose.
