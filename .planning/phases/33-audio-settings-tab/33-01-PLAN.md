## Artifacts this phase produces

- `AudioSettings` immutable value object for EQ preset index, balance, sync milliseconds, and normalization state.
- `AudioFilterCompositor` with the deterministic EQ → balance → delay → normalization chain assembly seam.
- `SettingsStore.loadAudioEqPreset`, `loadAudioBalance`, `loadAudioSyncMs`, `loadAudioNormalization`, and matching `saveAudio*` APIs.
- `SettingsPanelController` audio registration and typed audio commit callback seam.
- Deferred-apply `EqualizerTab` EQ preset UI.
- Wave 0 target-Windows filter availability smoke check and runtime fallback policy.

## Research resolutions

- **Q1 — Filter availability:** Before composing a production chain, run individual `pan`, `adelay`, and `dynaudnorm` checks against the target fvp 0.37.2 runtime. A filter whose `setEqualizer` call throws is marked unavailable; every later composed af chain omits that segment and emits a `debugPrint` warning while the UI continues to retain and commit the raw control value.
- **Q2 — Commit integration:** Use Option A: inject a typed `AudioCommitCallback` into `SettingsPanelController`; `PlayerFeature` registers it at the composition root, composes the received pending audio snapshot, calls the existing engine entry, and persists the raw values.
- **Q3 — Rendered tab:** `tab_content.dart` imports `tabs/equalizer_tab.dart`; Phase 33 replaces that skeleton as the combined first audio tab. The root-level legacy `equalizer_tab.dart` is not rendered and remains untouched.
