    - Expand class doc comment: explain this wraps SettingsStore window writes with two optimizations: (1) debounce 150ms to coalesce rapid WM_SIZE/WM_MOVE events during drag/resize (~60fps = ~16ms per event), (2) write lock to prevent concurrent SharedPreferences writes from corrupting state
    - Add why-explanation to `debounceMs = 150`: // 150ms 防抖 — 略大于 16ms 帧间隔，确保拖拽/resize 期间只触发一次保存
    - Add why-explanation to `_enqueue` write lock pattern: explain the "latest wins" strategy — when a save is in-flight and new data arrives, only the latest values are kept (not queued). This is correct because window geometry is a "last write wins" scenario
    - Add why-explanation to `saveIsFullscreen` being immediate (no debounce): // 全屏切换是离散事件，不需要防抖

    **display_enumerator.dart (DOC-15):**

    - Expand library doc comment: explain this defines the platform-agnostic display enumeration interface. Platform implementations (Win32, macOS, Linux) provide concrete enumerators. ScreenUtils uses this interface for multi-monitor window clamping
    - Expand `DisplayInfo` class doc comment: explain `bounds` is the full monitor area (including taskbar), `workArea` is the usable area (excluding taskbar), `isPrimary` identifies the main display. All coordinates are in Flutter logical pixels (not physical pixels)
    - Add why-explanation to `bounds` vs `workArea` distinction: // bounds 含任务栏，workArea 排除任务栏 — 窗口钳制用 workArea 避免被任务栏遮挡

    - Add why-explanation to `_rectToFlutter` DPR division: // Win32 返回物理像素，Flutter 使用逻辑像素 — 除以 devicePixelRatio 转换坐标系

    - Expand Win32DisplayAdapter class doc comment: explain when to use which — Win32DisplayEnumerator for direct static calls (internal), Win32DisplayAdapter for DI into ScreenUtils (external)
