    扩展 fullscreen_window 的 Linux 插件，添加 window-state-event 信号监听 (D-P12)。

    **C++ 修改 (fullscreen_window_plugin.cc):**

    1. 添加信号回调函数:
       ```cpp
       static gboolean on_window_state_changed(GtkWidget *widget,
           GdkEventWindowState *event, gpointer user_data) {
         FullscreenWindowPlugin *plugin = FULLSCREEN_WINDOW_PLUGIN(user_data);
         if (event->changed_mask & GDK_WINDOW_STATE_FULLSCREEN) {
           gboolean is_fullscreen =
               event->new_window_state & GDK_WINDOW_STATE_FULLSCREEN;
           // 通过 MethodChannel 通知 Dart 层
           g_autoptr(FlValue) args = fl_value_new_map();
           fl_value_set_string_take(args, "isFullScreen",
               fl_value_new_bool(is_fullscreen));
           fl_method_channel_invoke_method(plugin->channel,
               "onFullScreenChanged", args, NULL, NULL, NULL);
         }
         return FALSE; // 不拦截事件，继续传播
       }
       ```

    2. 修改 `_FullscreenWindowPlugin` 结构体:
       - 添加 `FlMethodChannel *channel;` 字段

    3. 修改 `fullscreen_window_plugin_register_with_registrar`:
       - 保存 channel 引用: `plugin->channel = fl_method_channel_ref(channel);`
       - 在获取 window 后注册信号: `g_signal_connect(G_OBJECT(gtk_widget_get_toplevel(GTK_WIDGET(view))), "window-state-event", G_CALLBACK(on_window_state_changed), plugin);`
       - 注意: 需要在 get_window 可用时注册。如果 view 为 NULL，延迟注册

    4. 修改 `fullscreen_window_plugin_handle_method_call`:
       - 添加 `getFullScreenState` 方法处理: 查询 `GdkWindow` 状态
         ```cpp
         GdkWindow *gdk_window = gtk_widget_get_window(GTK_WIDGET(get_window(self)));
         gboolean is_fullscreen = gdk_window_get_state(gdk_window) & GDK_WINDOW_STATE_FULLSCREEN;
         ```
       - 添加 `getPlatformNotes` 方法: 返回 WM 类型信息 (D-P13)

    5. 修改 `fullscreen_window_plugin_dispose`:
       - 释放 channel: `g_clear_object(&self->channel);`

    **Dart 修改:**

    如果 Plan 02 (macOS) 已完成 MethodChannel 回调支持，Linux 的 Dart 端修改与 macOS 共享同一套代码 (fullscreen_window_method_channel.dart 的 onFullScreenChanged 流)。如果 Plan 02 尚未完成，需要:
    - 在 fullscreen_window_method_channel.dart 中添加 `setMethodCallHandler` 处理 `onFullScreenChanged`
    - 在 fullscreen_window_platform_interface.dart 中添加 `Stream<bool> get onFullScreenChanged`

    **关键注意事项:**
    - `window-state-event` 信号在 X11 和 Wayland 下行为可能不同 (研究 Assumption A5)
    - 平铺 WM (i3/Sway) 可能不触发此信号 — 三级确认链的 Level 2 轮询兜底
    - 信号回调中 `event->changed_mask` 检查确保只处理 fullscreen 相关变化
    - MethodChannel 调用在 GLib 主线程执行，Flutter 引擎处理线程安全

    创建 `lib/kernel/bridge/platform/linux_fullscreen_driver.dart` — Linux GTK 全屏驱动。

    **类设计:**

    `LinuxFullscreenDriver` implements `FullscreenDriver`。

    构造函数注入:
    ```dart
    LinuxFullscreenDriver({
      FullScreenWindowPlatform? plugin,
      WindowManager? wm,
    }) : _plugin = plugin ?? fullScreenWindow,
         _wm = wm ?? windowManager;
    ```

    **内部组件:**
    - `_plugin: FullScreenWindowPlatform` — fullscreen_window 插件 (全屏操作)
    - `_wm: WindowManager` — window_manager (其他窗口操作)
    - `_stateStreamSub: StreamSubscription<bool>?` — 监听原生回调流
    - `_onNativeCallback: void Function(int windowId, bool isFullscreen)?` — 通知 Adapter 的回调
    - `_wmInfo: String` — 运行时 WM 检测结果 (D-P13)

    **WM 检测 (D-P13):**

    `_detectWindowManager()` 方法:
    - 读取 `Platform.environment['XDG_SESSION_TYPE']` → "x11" 或 "wayland" 或 "unknown"
    - 读取 `Platform.environment['XDG_CURRENT_DESKTOP']` → 桌面环境名 (如 "GNOME", "KDE")
    - 读取 `Platform.environment['GDMSESSION']` → 会话名
    - 读取 `Platform.environment['DESKTOP_SESSION']` → 备用会话名
    - 组合为 `'session=$sessionType, desktop=$desktop, wm=$wmName'`
    - debugPrint 记录到日志: `debugPrint('[LinuxFullscreenDriver] WM detected: $_wmInfo')`
    - 在构造函数中调用

    **原生回调桥接 (D-P12):**
    - 设置 setter: `set onNativeStateChanged(void Function(int, bool)? callback)`
    - 构造函数中订阅 `_plugin.onFullScreenChanged` 流 (如果可用):
      ```dart
      _stateStreamSub = _plugin.onFullScreenChanged?.listen((isFullscreen) {
        _onNativeCallback?.call(0, isFullscreen);
      });
      ```

    **方法实现:**

    1. `enterFullscreen({int displayId = 0})`:
       - 调用 `_plugin.setFullScreen(true)`
       - 不等待确认 — Adapter 的三级确认链处理

    2. `leaveFullscreen()`:
       - 调用 `_plugin.setFullScreen(false)`

    3. `queryFullscreen()`:
       - 优先调用 `_plugin.isFullScreen()` 查询真实状态
       - 回退到 `_wm.isFullScreen()`

    4. `getPosition()` / `getSize()` / `setBounds()` / `maximize()` / `restore()` / `focus()` / `isMaximized()` / `isMinimized()`:
       - 全部委托给 `_wm`

    5. `capabilities()`:
       - 返回 `FullscreenCapability(supportsFullscreen: true, supportsMultiWindow: false, supportsMultiDisplay: true, supportsExclusive: false, requiresUserGesture: false, platformNotes: 'GTK fullscreen via fullscreen_window plugin. WM: $_wmInfo. Three-tier confirmation (callback → poll → timeout). Tiling WMs (i3, Sway) may have non-standard behavior.')`

    6. `dispose()`:
       - 取消 `_stateStreamSub` 订阅

    **单元测试 (test/platform/linux_fullscreen_driver_test.dart):**

    MockFullScreenWindowPlatform + MockWindowManager。

    测试用例:
    - enterFullscreen 调用 plugin.setFullScreen(true)
    - leaveFullscreen 调用 plugin.setFullScreen(false)
    - queryFullscreen 委托给 plugin.isFullScreen()
    - 原生回调触发时通知 onNativeStateChanged
    - capabilities 包含 WM 检测信息 (platformNotes 非空)
    - capabilities platformNotes 包含 "Three-tier confirmation"
    - window 管理方法委托给 window_manager
    - dispose 取消流订阅
    - WM 检测: 验证 _detectWindowManager 在无环境变量时不崩溃
