  <behavior>
    - enqueue 单个命令 → 立即执行 executor callback
    - enqueue 第二个命令时前一个 in-flight → 入队等待，executor 只调用一次
    - enqueue 相同目标命令（如两次 setFullscreen(true)） → 合并为一次执行
    - enqueue toggle → 先解析为 setFullscreen(true/false) 再参与合并
    - executor 超过 5 秒 → 自动取消并报 BusyTransition 错误
    - executor 正常完成 → 从队列取出下一个待执行命令
    - dispose 后 enqueue → 抛出 StateError
    - 不同 windowId 的命令 → 完全隔离，互不影响
    - 取消当前 in-flight 命令 → 释放队列等待的下一个命令
  </behavior>
  <action>
    创建 `lib/kernel/bridge/fullscreen_command_queue.dart`:

    **类设计:**
    - `FullscreenCommandQueue` 泛型类，executor 为 `Future<bool> Function(FullscreenRequest)` 回调
    - 内部维护 `_inFlight` (当前执行中)、`_pending` (待执行) per windowId
    - 使用 `Completer<bool>` 链实现串行化

    **per D-15:** FullscreenCommandQueue 作为独立类，FullscreenAdapter 内部持有。职责分离清晰，可独立测试。

    **per D-14:** per-windowId 独立队列。每个 windowId 一个独立的队列实例，多窗口完全隔离。

    **核心方法:**
    - `Future<bool> enqueue(FullscreenRequest request)` — 入口方法，返回命令执行结果
    - `bool _canMerge(FullscreenRequest pending, FullscreenRequest incoming)` — 合并判断
    - `FullscreenRequest _resolveToggle(ToggleFullscreen toggle, bool currentFullscreen)` — toggle 解析
    - `void _drainQueue(int windowId)` — 执行完成后处理下一个
    - `void cancel(int windowId)` — 取消当前 in-flight 命令
    - `void dispose()` — 清理所有资源

    **per D-17:** 合并规则:
    1. toggle 先解析为 setFullscreen(true/false) 再参与合并
    2. 只在同一 windowId 下、且目标相同才合并
    3. 具体实现: `_canMerge` 比较 `request.windowId` + 请求类型 + 目标状态

    **per D-13:** 5 秒超时 + BusyTransition 错误。使用 `Future.timeout(Duration(seconds: 5))` 包裹 executor 调用。超时后:
    1. 取消当前执行
    2. 完成 Completer 并抛出 BusyTransition
    3. 尝试 drain 队列中的下一个

    **per D-16:** 命令开始执行时才更新 phase。队列本身不管理 phase，由调用方（DesktopFullscreenAdapter）在执行回调中更新。

    **队列状态机:**
    - idle: 无 in-flight 命令
    - executing: 有 in-flight 命令，可能有 pending
    - 每个 windowId 独立维护状态

    **注意:**
    - 不要引入 `fullscreen_window` 或 `window_manager` 依赖 — 纯 Dart 逻辑
    - 使用 `Timer` 实现超时，dispose 时取消所有 Timer
    - executor 回调的返回值（bool）表示成功/失败，队列负责传播结果

    **P1-5: dispose 生命周期策略（冻结）:**
    - dispose 后 `_disposed = true`，新 enqueue 抛出 StateError
    - pending 的 Completer 立即 complete(false) — 不悬挂
    - in-flight 的命令：不取消（让 executor 自然完成），但完成后不 drain pending
    - 超时 Timer 在 dispose 中 cancel
    - 文档注释明确：dispose 后 in-flight 的 Future 仍会 resolve（true/false），但不会触发后续操作

    创建测试 `test/kernel/bridge/fullscreen_command_queue_test.dart`:
    - 使用同步的 mock executor（`() async => true`）测试队列逻辑
    - 使用延迟的 mock executor（`Future.delayed`）测试并发和超时
    - 测试 toggle 解析为 setFullscreen(true/false) 的合并行为
