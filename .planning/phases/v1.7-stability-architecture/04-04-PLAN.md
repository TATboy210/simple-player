# Wave 4 Plan 04: ValueNotifier Thread Safety

## Objective

确保所有从平台回调（MethodChannel/FFI）更新 ValueNotifier 的代码都在 UI 线程执行，防止 macOS/Linux 平台线程不一致导致的崩溃。

**Purpose:** 预防跨平台移植时的线程安全问题。
**Output:** 所有平台回调中的 ValueNotifier 更新使用 `SchedulerBinding.instance.addPostFrameCallback` 或 `WidgetsBinding.instance.addPostFrameCallback`。

## Context

当前状态:
- `WindowService` 实现 `WindowListener`，OS 回调（`onWindowMaximize` 等）直接更新 `ValueNotifier.value`
- `Win32PlatformFullscreen.enter()` 在 FFI 调用后返回 `FullscreenSnapshot`
- `LinuxPlatformFullscreen` 使用 MethodChannel 获取 GTK 窗口句柄
- `MacosPlatformFullscreen` 使用 MethodChannel 调用 NSWindow API
- Flutter 的 `ValueNotifier.value = x` 会触发 `notifyListeners()`，必须在 UI 线程

关键约束:
- Win32 上 `WindowListener` 回调在 UI 线程（Dart isolate），目前安全
- macOS 上 `WindowListener` 回调可能在 platform thread
- FFI 回调（如 `NativeCallable.isolateLocal`）在 Dart isolate，安全
- MethodChannel 回调默认在 platform thread，需要调度到 UI 线程

## Tasks

### Task 1: WindowService 回调线程安全

**文件:**
- `lib/kernel/bridge/window_service.dart`

**Action:**
在 `WindowService` 的 `WindowListener` 回调中，确保 ValueNotifier 更新在 UI 线程:

1. 修改 `lib/kernel/bridge/window_service.dart`:
   - 添加导入: `import 'package:flutter/scheduler.dart';`
   - 创建辅助方法:
     ```dart
     /// 确保 ValueNotifier 更新在 UI 线程执行。
     ///
     /// macOS/Linux 的 WindowListener 回调可能在 platform thread，
     /// 直接更新 ValueNotifier 会触发 notifyListeners() 跨线程崩溃。
     void _updateOnUIThread(VoidCallback update) {
       if (SchedulerBinding.instance.schedulerPhase == SchedulerPhase.idle ||
           SchedulerBinding.instance.schedulerPhase == SchedulerPhase.postFrameCallbacks) {
         update();
       } else {
         SchedulerBinding.instance.addPostFrameCallback((_) => update());
       }
     }
     ```
   - 修改 `onWindowMaximize()`:
     ```dart
     @override
     void onWindowMaximize() {
       if (_disposed) return;
       _startResizeEndTimer();
       _updateOnUIThread(() {
         if (_state.mode.value != WindowMode.maximized) {
           _state.mode.value = WindowMode.maximized;
         }
       });
     }
     ```
   - 修改 `onWindowUnmaximize()`、`onWindowResize()` 同样使用 `_updateOnUIThread`
   - 注意: `_startResizeEndTimer()` 内部的 `_state.isResizing.value = true` 也需要保护

2. 修改 `_startResizeEndTimer()`:
   ```dart
   void _startResizeEndTimer() {
     _resizeEndTimer?.cancel();
     _updateOnUIThread(() => _state.isResizing.value = true);
     _resizeEndTimer = Timer(
       Duration(milliseconds: _durationResizeEnd),
       () {
         if (!_disposed) {
           _updateOnUIThread(() => _state.isResizing.value = false);
         }
       },
     );
   }
   ```

### Task 2: FullscreenController 回调线程安全

**文件:**
- `lib/kernel/bridge/fullscreen_controller.dart`

**Action:**
确保 `FullscreenController.setFullscreen()` 中的 ValueNotifier 更新在 UI 线程:

1. 修改 `lib/kernel/bridge/fullscreen_controller.dart`:
   - 添加导入: `import 'package:flutter/scheduler.dart';`
   - 在 `setFullscreen()` 的 success path 中，`state.mode.value = WindowMode.fullscreen` 和 `state.mode.value = previousMode` 确保在 UI 线程
   - 由于 `setFullscreen()` 是从 UI 层调用的（用户按键），当前已经在 UI 线程，但为了防御性编程:
     ```dart
     // 在 setFullscreen 的 success path
     if (enter) {
       _savedSnapshot = await _platform.enter();
       _safeUpdateMode(WindowMode.fullscreen);
     } else {
       // ...
       _safeUpdateMode(previousMode);
     }
     ```
   - 添加辅助方法:
     ```dart
     void _safeUpdateMode(WindowMode mode) {
       if (SchedulerBinding.instance.schedulerPhase == SchedulerPhase.idle ||
           SchedulerBinding.instance.schedulerPhase == SchedulerPhase.postFrameCallbacks) {
         state.mode.value = mode;
       } else {
         SchedulerBinding.instance.addPostFrameCallback((_) {
           state.mode.value = mode;
         });
       }
     }
     ```

2. 同样保护 `state.windowSize.value = _savedSize!` 的更新

### Task 3: 平台全屏实现线程安全审查

**文件:**
- `lib/kernel/bridge/win32/win32_platform_fullscreen.dart`
- `lib/kernel/bridge/linux/linux_platform_fullscreen.dart`
- `lib/kernel/bridge/macos/macos_platform_fullscreen.dart`

**Action:**
审查并修复平台全屏实现中的线程安全问题:

1. `Win32PlatformFullscreen`:
   - `enter()` 使用 FFI 同步调用，在 Dart isolate 执行，安全
   - `exit()` 同样安全
   - 无需修改

2. `LinuxPlatformFullscreen`:
   - `_getGtkWindowAsync()` 使用 MethodChannel，回调在 platform thread
   - `_gtkWindowFullscreen!` 和 `_gtkWindowUnfullscreen!` 是 FFI 调用，在 Dart isolate
   - `_exitAsync()` 中的 `_gtkWindowUnfullscreen!` 在 `await` 后执行，可能在不同 isolate
   - 修复: 确保 FFI 调用在正确的 isolate（使用 `Isolate.run` 或保持在主 isolate）

3. `MacosPlatformFullscreen`:
   - `enter()` 使用 MethodChannel，回调在 platform thread
   - `exit()` 使用 MethodChannel，回调在 platform thread
   - 这些方法返回 `Future`，调用方 `await` 后在 UI 线程继续
   - 无需修改（`await` 会调度回 UI isolate）

4. 添加文档注释说明线程模型:
   ```dart
   /// 线程模型:
   /// - enter()/exit() 在 UI isolate 调用
   /// - FFI 调用在 UI isolate 执行（Dart FFI 限制）
   /// - MethodChannel 调用自动调度回 UI isolate（await 机制）
   ```
