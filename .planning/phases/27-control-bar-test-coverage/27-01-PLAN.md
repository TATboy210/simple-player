# Phase 27: Control Bar Test Coverage

## Problem Statement

控制栏核心组件有 ~120 个既有测试，但关键行为路径存在覆盖盲区：
- **3 个文件零测试**：KeyboardHandler（228 行，18+ 快捷键）、DropHandler、PlayerScreen
- ProgressBar 的 5px 拖拽阈值和150ms seek 节流无测试
- SpeedButton 的箭头点击、双击重置、非标准值吸附无测试
- VolumeButton 的自动取消静音、精确音量恢复无测试
- AutoHideController 的 resize 冻结和 hover 节流边界时序无测试
- ControlsOverlay 的 resize 流程（淡出/淡入、engine 状态冻结）无测试
- ControlBar 的响应式布局断点（ultra-compact/compact）无测试

这些盲区恰好对应用户高频交互路径，回归风险最高。

## Risk Assessment

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| KeyboardHandler 测试需要 Focus 集成 | Medium | 使用 `tester.sendKeyDownEvent` + `Focus` wrapper |
| DropHandler 测试需要模拟拖放事件 | Medium | 使用 `PointerDropEvent` 构造或 TestDefaultBinaryMessenger |
| PlayerScreen 测试需要大量依赖注入 | Medium | 最小化 FakeEngine + ValueNotifier 组合 |
| ProgressBar 拖拽阈值测试因手势模拟精度失败 | Medium | 使用明确 >5px 和 <5px 的 offset，留 1px 余量 |
| SpeedButton 双击被识别为两次单击 | Medium | 使用 `tester.tap` 快速连续调用 |
| 60 个测试一次性实现耗时过长 | Low | 分 WAVE 实现，每 WAVE 独立验证 |
