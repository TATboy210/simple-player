本次会话完成的调研：

### 播放器全屏方案分析
- **mpv** — C 原生程序，Win32 API `SetWindowLong` + `SetWindowPos`，无 FFI 需求
- **VLC** — 同 mpv，原生 C，直接 Win32 API
- **射手影音 (SPlayer)** — MPC-HC fork，`ModifyStyle(WS_CAPTION|WS_THICKFRAME)` + 一次 `SetWindowPos` + `RedrawNonClientArea`。源码注释承认会闪烁

### Flutter 生态包分析
- **fullscreen_window v1.2.1** — 120 行核心代码，Windows 用 `SC_MAXIMIZE` 消息（非 SetWindowPos），WS_EX_TOPMOST 设了但不清理（bug）。Linux 用 `gtk_window_fullscreen` 原生 API
- **window_manager** — 4 次 SetWindowPos = 4 次重绘，无焦点恢复、无 TopMost 清理、无状态验证。退出全屏时 FindWindowEx("FLUTTERVIEW") + SetWindowPos 刷新子窗口（值得借鉴）
- **fullscreen_window C++ plugin** — 最简单方案，SC_MAXIMIZE 一行搞定

### 核心发现
1. **所有方案最终都调 Win32 API** — MethodChannel / FFI / 消息只是 Dart→C 的通信方式不同
2. **闪烁根因是 Flutter 渲染管线** — 异步 Texture 合成跟不上 WM_PAINT 频率，不是 API 调用方式问题
3. **原生框架 (Qt/WPF/WinUI) 零闪烁** — 同步绘制，WM_PAINT 到达时立即画好
4. **Electron/Tauri 轻微闪烁** — Chromium 持久化 D3D Surface，比 Flutter 好但不完美
5. **换框架不值得** — Flutter 内优化可解决，成本远低于重写

### 可借鉴的优化方案
- `SC_MAXIMIZE` 代替 `SetWindowPos`（让 DWM 理解意图）
- `SWP_FRAMECHANGED` 退出全屏时强制重绘
- 先铺屏再去边框（减少中间状态）
- Fade 黑色遮罩 200ms 过渡（用户感知零闪烁）
- FindWindowEx("FLUTTERVIEW") 刷新 Flutter 子窗口（window_manager 方案）
