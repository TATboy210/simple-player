# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: WM_NCCALCSIZE ordering — WndProc is the earliest message entry point, intercept there (NOT in MessageHandler where HandleTopLevelWindowProc runs first). 3 prior C++ attempts failed because they put the handler in MessageHandler.
- [ ] CONSTRAINT: Triple border removal conflict — window_manager plugin + main.dart FFI + app.dart WindowService.init() create 3 async paths. C++ WM_NCCALCSIZE handles it synchronously, all 3 Dart paths can be removed.
- [ ] CONSTRAINT: Fullscreen compatibility — use WS_POPUP self-check in WndProc (方案 B), no extra FFI bindings needed.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| MessageHandler interception | Putting WM_NCCALCSIZE in FlutterWindow::MessageHandler — engine consumes it first | blocking | Intercept in WndProc (static callback, before MessageHandler) |
| Async border removal race | Dart-side removeBorderImmediate() races with windowManager.show() — one-frame flash | blocking | C++ synchronous WM_NCCALCSIZE; remove all Dart async border paths |
| _savedFrame memory leak | Overwriting _savedFrame without freeing old pointer | high | Free old value before allocating new one |
