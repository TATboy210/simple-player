# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through research grounding
> against the live codebase (v3.0 milestone definition). The roadmapper AND every Phase 1+ plan
> must honor them. Acknowledge each one explicitly before proceeding.

- [ ] **CONSTRAINT: logger 决策语义校正** — `log.dart` 已 `import package:logger + path_provider`，121 调用点/30 文件。零依赖 = 内核解耦 `package:logger`（保留 `log*.w()` 调用形状的替换迁移），**非"app 无 logger 包"**。KernelLogger 是替换迁移不是新建。 — Phase 3 硬要求：LOG-04（保留调用形状）+ LOG-01（内核永不 import package:logger，CI grep 闸门）。勿从零写门面。
- [ ] **CONSTRAINT: 9 态 vs 6 态矛盾** — PROJECT.md 写 9 态 ~40 边，但 `engine_state_machine.dart` 当前 6 态。未核对会让适配层契约分叉。 — Phase 1（BASE-03）必须核对决定冻结基线 + v3.0 须补的 lifecycle 态（disposed/disposing/error-恢复），再固化 BCS。
- [ ] **CONSTRAINT: openGeneration 与状态机分离** — `openGeneration` 在 `fvp_engine.dart:194`，与 `engine_state_machine.dart` 分离；两者是同一正确性属性（"仅最新 open 的结果生效"）的两半。 — Phase 6（STATE-02）须用 `OpenGenerationTracker` 统一，守卫移入机器，`transitionTo` 原子拒绝过时 generation。
- [ ] **CONSTRAINT: EngineStateMachine 静默忽略非法转换** — `engine_state_machine.dart:52-58` 用 assert-only 静默忽略非法转换（release 无效），是项目记忆里的"静默失败"反模式。 — Phase 6（STATE-03）替换为 `Result.err` + KernelLogger 警告。
- [ ] **CONSTRAINT: MemoryMonitor 单例→实例原子提交** — 项目记忆 R2-5：删 `_instance` 但留静态方法致构建失败。MemoryMonitor 仅 2 静态调用（`main.dart:16`, `debug_exporter.dart:57`）。 — Phase 5（MEM-04）在一个原子提交内：瞬态静态桥 shim + 重写 2 调用 + 删 shim，**永不跨提交拆分**。
- [ ] **CONSTRAINT: 适配层转发 ValueNotifier 实例非重新包装** — KernelAdapter 若重新包装 ValueNotifier 会脱钩所有 ValueListenableBuilder 监听器 → cutover 时 UI 静默冻结。 — Phase 2（ADAPT-03）适配层返回活动引擎持有的同一 notifier 实例。
- [ ] **CONSTRAINT: debugPrint 发布不剥离** — debugPrint 在 release 仍在二进制中执行（throttled print）。零依赖门面须用 `kDebugMode` 门控，warn/error 走 `dart:developer.log`。 — Phase 3（LOG-03）+ Phase 7（VERIFY-06 --release 冒烟闸门）。
- [ ] **CONSTRAINT: 过度工程化是项目宿敌** — 项目记忆：此前重构产"27 文件 3500 行""19 变量管 1 bool""双数据源"。兼容替换易诱发永久 god-adapter 层。 — Phase 2（ADAPT-05）尺寸预算：适配层+门面+sealed 错误+tracker 合计 < 旧 FvpEngine；适配层除 KernelMode + generation 计数器外无状态；Phase 2 须召 senior-architect/red-team 挑战范围蔓延。

**Do not proceed until all boxes are checked.** 路线图生成时这 8 项必须固化为各 Phase 硬要求。

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| 静默失败 | EngineStateMachine assert-only 非法转换（release 无效），静默忽略错误 | blocking | Phase 6 换 Result.err + KernelLogger 警告（STATE-03） |
| 跨提交拆分单例重构 | R2-5 删 _instance 留静态方法致构建失败 | blocking | MemoryMonitor 单例→实例在**一个原子提交**内完成 shim+重写+删 shim（MEM-04） |
| ValueNotifier 重新包装 | 适配层包装 notifier 致 ValueListenableBuilder 监听器脱钩，UI 冻结 | blocking | 适配层转发活动引擎同一 notifier 实例（ADAPT-03） |
| 一次性 big-bang 替换内核 | 适配层不存在就重写状态机，替换引擎成禁断 swap | blocking | 适配层须先于状态重写存在，构建顺序 P1 契约→P2 适配→P3+... |
| 永久 god-adapter 层 | 兼容替换诱发过度工程化，适配层膨胀 | blocking | 尺寸预算合计 < 旧 FvpEngine + red-team 挑战范围蔓延（ADAPT-05） |
| logger 误解为新建门面 | 误把 KernelLogger 当全新门面从零写 | advisory | 它是替换迁移（保留 log*.w() 调用形状），非新建；内核永不 import package:logger |
