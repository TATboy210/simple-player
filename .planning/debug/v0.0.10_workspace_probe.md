# v0.0.10 Pub Workspace 最小实测 — 结论文档

> **目的**: 用临时目录双包骨架实测 Pub Workspace (Dart 3.6+) 的 4 项机制, 以真实 `dart pub get` / `dart run` 证据替代猜测, 为"本仓是否启用 workspace"给出有依据的裁决。

> **Toolchain**: Dart 3.13.5 / Flutter 3.47.6 / Windows 11 Home China 10.0.26200

## 结论

**本仓为单包应用, 无共享代码诉求, 不启用 Pub Workspace。** 启用反而引入根 pubspec (`name: _` + `workspace:` list) 与 `resolution: workspace` 解析复杂度, 违背 Unix 九原则之"小即是美"与"只做好一件事"。单包 repo 的依赖解析已由现有 `pubspec.yaml` + `pubspec.lock` 完整解决, workspace 不提供净收益。

实测确认 workspace 解析机制本身正常工作 (4/4 探针全 WORKS): `dart pub get` 在根生成单一锁文件、跨包 `package:helper/helper.dart` import 打印 `hello, world`、`meta` 依赖在 `^1.11.0` 与 `^1.12.0` 两约束下解析为单一 `1.19.0`、成员目录内 `dart pub get` 显式回溯根目录解析且不产生成员本地锁文件。机制可用性不是否决理由——本仓结构不需要它才是。

否决的依据是适用性而非可行性: 本仓当前只有一个可发布包 (`simple_player_flutter`), 无被两个及以上消费者共享的子包。在共享消费关系不存在时启用 workspace, 等于为一个不存在的耦合购买抽象, 违背 YAGNI。`window_frame_kit` 风格的子包结构若未来入驻, 届时再启用不迟 (见下文适用场景)。

## 适用场景

何时**应当**启用 Pub Workspace (enable-condition: 共享包被 ≥2 个消费者消费, 且当前为真):

- **若未来拆出 kernel 共享包** (如 `simple_player_kernel`) 被主 app 与外部测试/工具消费 — 此时 workspace 让多包共享同一份 lockfile, 避免跨包版本漂移; enable-condition = kernel 包存在且被主 app + ≥1 外部消费者同时引用。
- **若 window_frame_kit 式子包结构入驻本仓** (多包 monorepo, 如 `app/` + `window_frame_kit/` + `shared/`) — workspace 提供单一 `dart pub get` 入口与统一锁文件, 跨包路径依赖自动解析; enable-condition = 本仓出现 ≥2 个可独立解析的 pub 包。
- **若出现多个 app 共享同一 helper/domain 包** (如桌面 app + CLI 工具共享 `domain/`) — workspace 让共享包的版本约束在所有消费者间一致; enable-condition = 同一共享包被 ≥2 app 消费。

以上三条均以"共享包被 ≥2 消费者消费"为前提。在该前提变为现实之前 (YAGNI), workspace 保持关闭。这一取舍对应 Unix 九原则之"软件杠杆"(复用成熟库) 与"小即是美"(单包能解则不引多包复杂度) 的平衡: 共享真实存在时杠杆收益大于复杂度成本, 共享不存在时复杂度成本无对应收益。

## 实测记录

### 骨架布局 (临时目录 `$TEMP/ws_probe/`, 实验后已删除)

```
$TEMP/ws_probe/
├── pubspec.yaml              # workspace 根: name: _ + workspace: [app, helper]
├── app/
│   ├── pubspec.yaml          # 成员: resolution: workspace, deps: helper(path) + meta ^1.11.0
│   └── bin/
│       └── app.dart          # import 'package:helper/helper.dart'; print(helperGreet('world'))
└── helper/
    ├── pubspec.yaml          # 成员: resolution: workspace, deps: meta ^1.12.0 (故意不同下限)
    └── lib/
        └── helper.dart       # library helper; String helperGreet(String who) => 'hello, $who';
```

### 1. dart pub get 解析

- **exit_code**: 0
- **stdout**: `Resolving dependencies... Downloading packages... + meta 1.19.0 Changed 1 dependency!`
- **stderr**: (空)
- **observation**: 根目录生成 `pubspec.lock`, `app/` 与 `helper/` 均无成员本地锁文件
- **verdict**: WORKS

### 2. 跨包 import

- **exit_code**: 0
- **stdout**: `hello, world`
- **stderr**: (空)
- **observation**: stdout 包含 `hello, world`, 证明 `package:helper/helper.dart` 路径依赖在 workspace 解析下成功解析
- **verdict**: WORKS

### 3. 共享依赖锁版本

- **exit_code**: 0 (对 lockfile 的 grep)
- **stdout**: `meta_count=1, resolved version=1.19.0`
- **stderr**: (空)
- **observation**: `pubspec.lock` 中 `meta:` 包条目恰好 1 个, 解析版本 `1.19.0`, 同时满足 `app` 的 `^1.11.0` 与 `helper` 的 `^1.12.0` 两个下限约束 — 单一锁条目即共享约束证据
- **verdict**: WORKS

### 4. workspace 命令行为

- **exit_code**: helper=0, app=0
- **stdout (helper)**: `Resolving dependencies in \`.../ws_probe\`... Downloading packages... Got dependencies in \`.../ws_probe\`!`
- **stdout (app)**: `Resolving dependencies in \`.../ws_probe\`... Downloading packages... Got dependencies in \`.../ws_probe\`!`
- **stderr**: (均为空)
- **observation**: 在 `helper/` 与 `app/` 子目录内分别跑 `dart pub get`, 输出显式声明"在根目录 `ws_probe` 解析", 且两者均未生成成员本地锁文件 (helper=absent, app=absent)
- **verdict**: WORKS

### 实测命令与输出摘要

| 命令 | 退出码 | 关键输出 | 结论 |
