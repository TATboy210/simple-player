## Per-Category Detail

### 1. Isolate.runSync

- **analyze_exit**: 3
- **analyze_reason**: `error - isolate_run_sync.dart:7:26 - Instance member 'runSync' can't be accessed using static access. - static_access_to_instance_member`
- **run_exit**: N/A (compile failed)
- **Implication**: `Isolate.runSync(...)` 作为静态方法在 Dart 3.13.5 不存在。分析器将 `runSync` 解析为 Isolate 实例成员 (非静态)。**NO-GO** — B3 不得假设此 API 可用; 同步跨 isolate 调用仍需 `ReceivePort`/`SendPort` 或 `Isolate.run` (async)。

### 2. Isolate lifecycle (create + shutdownSync)

- **analyze_exit**: 3
- **analyze_reason**: `error - isolate_lifecycle.dart:8:30 - Too many positional arguments: 0 expected, but 1 found. - extra_positional_arguments_could_be_named`
- **run_exit**: N/A (compile failed)
- **Implication**: `Isolate.create` 名称解析到了某个成员, 但不接受位置函数参数 (0 expected)。`shutdownSync` 因编译在 `create` 处中断而未单独探测到。**NO-GO** — 干净的 create+shutdownSync 生命周期对在 3.13.5 不以探针假定的形态存在; B3 不得依赖此对。

### 3. List.unmodifiableOf

- **analyze_exit**: 0
- **run_stdout**: `COPY: view[0]=1 (defensive copy)`
- **Implication**: `List.unmodifiableOf(src)` 返回 **defensive copy**, 非 storage-sharing view。`src[0]=99` 后 `view[0]` 仍为 1。**27 站点迁移需逐站审计 (PER-CALL AUDIT)** — 现有 `List.unmodifiable(...)` 调用若依赖 view 语义 (源变更反映到视图), 迁移后行为会变; 若源在包装后不再变更, 行为等价可机械迁。B1 不得假定 mechanical migration。

### 4. NetworkInterface.list named params

- **analyze_exit**: 0
- **run_stdout**: `runtimeType=Future<List<NetworkInterface>>` + `OK: includeLoopback + type params present`
- **Implication**: `includeLoopback: bool` 和 `type: InternetAddressType` 命名参数均存在。**GO** — B3 可安全使用这些参数 (如 loopback 探测、IPv4/IPv6 过滤)。

### 5. @Native(assetId:) FFI 直连

三子模式均用 `GetDoubleClickTime` (user32 独有, 无副作用, 返回 UINT) — 比 `GetTickCount` (kernel32, 全局符号表可见) 更干净: 若 assetId='user32' 能解析它, 才证明 assetId 真做 DLL 隔离。

| Sub | analyze | run | stdout | verdict |
|-----|---------|-----|--------|---------|
| 5a `@Native(assetId:'user32')` 直调 | 0 | 0 | `500` | **GO** |
| 5b `DynamicLibrary.open('user32.dll')+lookupFunction` 基线 | 0 | 0 | `500` | **GO** |
| 5c `@Native`(无 assetId) + 预打开 user32 | 0 | 0 | `500` | **GO** |

- **Implication**: `@Native<Uint32 Function()>(symbol: 'GetDoubleClickTime', assetId: 'user32')` 无 native-assets build 注册即解析了 user32 独有函数 (返回 500ms double-click time)。**FFI batch disposition: 可采纳 `@Native assetId`** — B2 可用 `@Native(..., assetId: '<dll>')` 替代 `DynamicLibrary.open+lookupFunction`, 获得更短的声明式绑定。5c 表明无 assetId 时预打开 DynamicLibrary 也能让 @Native 解析 (兜底模式)。

### 6. Primary Constructor 语法矩阵

| PC feature | Compiles | Notes |
|------------|----------|-------|
| named + required + default (`class C(final int a, {required String b, int c = 7})`) | **Y** | `C(1, b:'x')` 构造成功 |
| const (`class P(final int x, final int y);` + `const P(1,2)`) | **N** | `const_initialized_with_non_constant_value` — PC 生成的构造器非 const-eligible |
| initializer list (`class R(final int x) : assert(x > 0)`) | **N** | `expected_body` — `: <body>` 初始化器形式不被 PC 语法支持 |
| sealed implicit super (`sealed class B(final int n); final class D extends B(5)`) | **N** | `no_default_super_constructor` — 子类 `extends B(5)` 隐式传参不被支持 |
| mutable + final mixed (`class M(final int id) { int count = 0; void inc() => count++; }`) | **Y** | final 主参 + 可变 body 字段共存合法 |
| head param doc (`class H(/// doc final int a)`) | **Y** | 头部参数 `///` 文档注释工作 |
| factory + new (`class F(final int v) { F.named(int v) : this(v); factory F.parse(...) }`) | **Y** | `this(v)` 重定向 + factory 与 PC 共存 |

- **Implication**: 4/7 PC 特性可用, 但 **const / initializer-list / sealed-implicit-super 三项不可用** — 这三项恰好是本仓库 PC 候选类普遍依赖的 (const 构造器、init-list 计算字段、sealed 层级)。**B1 PC 迁移批次基本被阻断** (见候选裁决表)。

### 7. @Native 树摇 (unused binding)

- **approach**: `dart compile exe` 两片段 — baseline (`void main(){}`) vs unused (`@Native external` 声明但 main 不调用), 比较 exe 体积。
- **baseline exe**: 6125056 B
- **unused exe**: 6125056 B
- **delta**: 0 B (≤ 2KB 容差)
- **Implication**: 未引用的 `@Native` external 声明被编译器树摇, 不膨胀二进制。**GO** — B2 可放心声明 `@Native` 绑定, 仅引用的符号进二进制; 无需手动 `@pragma('vm:entry-point')` 或删除未用绑定。

## Special Rulings

### player_error.dart — 不迁 (NO-MIGRATE)

五个子类 `FileError` / `CodecError` / `PlaybackError` / `NetworkError` / `UnknownError` 各自声明可变 `ErrorContext? context` 字段 (非 final, sealed 基类有 `set context`), 因为引擎在构造后丰富 context (enrichment)。PC 主参是 final, 故 `context` 不能作主参。即便 `pc_mutable_and_final_mixed` 探针确认混合类语法合法, 迁移这五个子类要么丢失 enrichment 能力, 要么把字段拆散到 header + body 无简洁收益。

**裁决: 保持原状。** 此裁决不依赖探针结果 — `context` 的可变语义是结构性约束。

### ErrorContext — 不迁 (NO-MIGRATE)

`ErrorContext` 的 `timestamp` 字段用 `timestamp ?? DateTime.now()` (运行时默认, 非常量) 在 init-list 中。PC 主参默认必须是常量表达式, 故 `timestamp` 不能把默认值作主参; 需 nullable 主参 + body 合并默认。但 `pc_initializer_list` 探针返回 **NO-GO** (`expected_body`), 确认 `: <body>` 形式不被 PC 语法支持。

**裁决: 不迁。** `DateTime.now()` 运行时默认 + PC init-list 不可用 = 双重阻断。

## Batch Dispositions

- **B1 (PC migration)**: **阻断 — 0/22 候选可迁。** PC const / init-list / sealed-implicit-super 三探针均 NO-GO, 而全部候选依赖这三项 (const 构造器或 init-list 计算字段)。B1 不得在 Dart 3.13.5 上执行任何 PC 迁移; 待 Dart 后续版本补齐 PC const + init-list 后重启评估。
- **B2 (FFI migration)**: **GO — 采纳 `@Native assetId`。** 依赖 cat 5 (assetId 解析 user32 独有函数 GO) + cat 7 (未用 @Native 树摇 GO, 无二进制膨胀)。B2 可用 `@Native<T>(symbol:, assetId:)` 替代 `DynamicLibrary.open+lookupFunction`, 5c 兜底模式 (无 assetId + 预打开 lib) 也可用。
- **B3 (other)**: **混合 — 按 cat 分别处置。** cat 3 `List.unmodifiableOf` GO 但 COPY 语义, 27 站点需逐站审计 (非 mechanical); cat 4 `NetworkInterface` named params GO 可用; cat 1 `Isolate.runSync` NO-GO 不可用; cat 2 `Isolate` lifecycle NO-GO 不可用。

## Threat Flags

无新增威胁面。探针仅用 SDK API + 公共 Win32 timestamp/double-click 函数 (只读), 无网络/无不可信输入/无密钥。`DynamicLibrary.open('user32.dll')` 是 T-quick-01 已接受 (low, accept) 的只读符号解析。
