**Step 1: Create FocusableSettingRow (lib/ui/shared/focusable_setting_row.dart)**

Create a new widget that wraps any child with focus detection and visual feedback:

- `FocusableSettingRow` StatelessWidget
- Parameters: `child` (Widget), `onFocusChange` (ValueChanged<bool>?), `enabled` (bool, default true), `autofocus` (bool, default false), `focusKey` (Key? for testing)
- Internal: Uses `FocusableActionDetector` (from `flutter/services.dart`) to detect focus + hover + press states
- When `enabled` is false: wrap child in `ExcludeFocus` + `IgnorePointer`, no visual feedback (D-15)
- Focus visual: `AnimatedContainer` with `BoxDecoration`:
  - Focused: `border: Border.all(color: Tokens.borderHighlight, width: 2)`, `borderRadius: BorderRadius.circular(Tokens.radiusSm)` (D-11)
  - Not focused: `border: Border.all(color: Colors.transparent, width: 2)` (same size to prevent layout jump)
- Hover visual: overlay `Tokens.bgHover` background when hovered AND not focused (D-12) - focus border takes precedence over hover background
- Focus animation: immediate, no animation on border change (D-13) - use `Duration.zero` for the border decoration transition
- Press visual: `Transform.scale(scale: Tokens.pressScale)` when pressed (reuse existing pattern from SettingRow)
- Padding: match SettingRow's existing `EdgeInsets.symmetric(horizontal: Tokens.spSm)` for alignment
- The `FocusableActionDetector` wraps the existing `AnimatedContainer`, NOT replacing it - it is a pure overlay layer
- Add `///` doc comment explaining purpose and D-11/D-12/D-13/D-15 decisions

```
            child: _buildContent()
        ),
        _buildButtonBar(),        // Wrapped in FocusTraversalGroup
      ]
```

- Add GlobalKeys for each FocusTraversalGroup to enable B-key focus group detection

**Step 5: Extend _handleKeyEvent for D-pad Up/Down and A/B key (NAV-04/NAV-05/NAV-06)**

Modify `_handleKeyEvent` in `_SettingsOverlayShellState` to handle the new navigation keys:

Current behavior preserved:
- ArrowLeft/ArrowRight on sidebar nav item -> prevTab/nextTab (D-04)
- LB/RB -> prevTab/nextTab (D-05)

New behavior added:
- **ArrowUp**: `FocusTraversalGroup.of(context).focusInDirection(TraversalDirection.up)` - moves focus to previous item in current group (NAV-01). If at top of group, do nothing (D-14 boundary stop).
- **ArrowDown**: `FocusTraversalGroup.of(context).focusInDirection(TraversalDirection.down)` - moves focus to next item in current group (NAV-01). If at bottom of group, do nothing.
- **A key (Enter)**: When a Switch is focused, toggle it. When a Button is focused, trigger it. Use `PrimaryAction` or simulate tap via `Actions.invoke` on the focused widget. (NAV-05 partial - SpinControl handled in Plan 02)
- **B key (Escape)**: Two-step close logic (NAV-06):
  - If focus is currently in the content area group -> move focus to the sidebar (first nav item)
  - If focus is currently in the sidebar or button bar -> close panel (existing behavior)
  - Implementation: use a GlobalKey on the content FocusTraversalGroup. Compare `Focus.of(context).nearestScope` against the content group's FocusNode to detect which group has focus.
- **ArrowLeft/ArrowRight on focused control**: When a Switch is focused, Left toggles off, Right toggles on (NAV-04 partial). When focus is NOT on a control (on sidebar nav item), keep existing tab-switch behavior (D-04).

Key routing logic order:
1. If `event is! KeyDownEvent` -> ignored
2. LB/RB -> tab switch (D-05) - always, regardless of focus position
3. B/Escape -> two-step close (NAV-06)
4. If focused widget is a control (Switch/Slider/Button):
   - ArrowLeft/ArrowRight -> adjust value (NAV-04)
   - Enter/A -> confirm action (NAV-05)
   - ArrowUp/ArrowDown -> move focus (NAV-01)
5. If focused widget is a sidebar nav item:
   - ArrowLeft/ArrowRight -> tab switch (D-04)
   - ArrowUp/ArrowDown -> move focus within sidebar
   - Enter/A -> select tab
6. Otherwise (title bar, button bar):
   - ArrowUp/ArrowDown -> move focus
   - Enter/A -> activate
