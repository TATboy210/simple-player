**Gamepad key constants (cross-platform, per research Pitfall 2):**
Windows embedder maps GAMEPAD_LEFT_SHOULDER(0xc8) to `LogicalKeyboardKey.gameButton13`, not `gameButtonLeft1`. Must check BOTH for cross-platform safety:
- Left Shoulder: `LogicalKeyboardKey.gameButton13 || LogicalKeyboardKey.gameButtonLeft1`
- Right Shoulder: `LogicalKeyboardKey.gameButton12 || LogicalKeyboardKey.gameButtonRight1`

Define two private helper methods at the end of `_SettingsOverlayShellState`:
```dart
bool _isLeftShoulder(LogicalKeyboardKey key) =>
    key == LogicalKeyboardKey.gameButton13 ||
    key == LogicalKeyboardKey.gameButtonLeft1;

bool _isRightShoulder(LogicalKeyboardKey key) =>
    key == LogicalKeyboardKey.gameButton12 ||
    key == LogicalKeyboardKey.gameButtonRight1;
```

**Key event handling order in `_handleKeyEvent`:**
1. Guard: `if (event is! KeyDownEvent) return KeyEventResult.ignored;`
2. ESC/B close (existing)
3. Arrow Left/Right → prevTab/nextTab (new)
4. Gamepad Left/Right Shoulder → prevTab/nextTab (new)
5. Default: `return KeyEventResult.ignored;`

**Why KeyEventResult.handled matters (D-06):**
Returning `handled` prevents the event from bubbling up to `KeyboardHandler` which would interpret Left/Right as seek ±5s. The panel's Focus node is inside `FocusTraversalGroup` which has priority over the outer `KeyboardHandler` Focus node.

**Important:**
- Do NOT modify any other methods or widgets
- Do NOT add new imports (LogicalKeyboardKey is from flutter/services.dart, already imported)
- Keep existing ESC/B behavior unchanged
- nextTab()/prevTab() already exist on controller from Plan 1
