<objective>
**用户故事：作为播放器用户，我希望错误卡片开关与诊断日志路径被持久保存、且日志始终落在第一个可写位置，以便重启后偏好仍在、错误证据从不丢失。**

本计划是 Phase 4 的 production tracer：贯通 `settings.json（便携 JSON，D-01）→ ErrorFeedbackSettings store → ErrorLogLocation.resolve 三层链（配置目录 → exe 根 logs/ → Application Support logs/，D-02 修订）→ ErrorLogFileSink 激活 → 诊断包落盘` 的端到端单一路径。随后把存储层加固到生产级（原子写 + 损坏矩阵，SET-03）。

Purpose: 这是 SET-02「可写性校验 + 回退链」与 SET-03「重启持久化」的地基层；后续计划（重定向协调器、卡片开关、设置 UI）全部从这个已验证的纵切展开。
Output: 便携设置存储、三层位置链（唯一允许的 kernel 编辑）、启动接线与两份测试文件。
</objective>
