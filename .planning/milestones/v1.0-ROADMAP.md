# Milestone v1.0: Window Management & UI Unification

**Status:** SHIPPED 2026-05-29
**Phases:** 1-5
**Total Plans:** 10 formal + 3 ad-hoc waves

## Overview

Build self-managed window control via MethodChannel + Win32 FFI, unify the glassmorphism component library, optimize playback performance, and clean up technical debt. Strategy: foundation first (window layer), then UI cleanup, then performance tuning, then quality.

## Milestone Summary

**Key Decisions:**

- Self-built MethodChannel for window management (no third-party packages)
- Windows first, macOS/Linux stubs follow
- Unified glass component library (GlassContainer/GlassButton/GlassIconButton)
- ValueNotifier pattern preserved (no state management migration)
- D3D11 sync default: synchronous for safety, user-tunable
- Architecture simplified from 4-layer to 3-layer (Kernel/Features/UI)

**Issues Resolved:**

- C++ WM_NCCALCSIZE + WM_NCHITTEST intercept precedence with Flutter's HandleTopLevelWindowProc
- DWMWA_WINDOW_CORNER_PREFERENCE one-frame right-angle flash on startup
- WS_THICKFRAME invisible border causing fullscreen blocking
- ControlsOverlay fragile cache invalidation pattern removed
- Static singletons untestable — added @visibleForTesting reset methods

**Technical Debt (Non-Blocking):**

- Phase 3 measurement gaps: multi-GPU D3D11 testing, frame time measurement, settings persistence
- Phase 1/4/5 missing formal VERIFICATION.md artifacts
- PLATFORM-02 (macOS/Linux stubs) intentionally deferred to v2

**Known Gaps:**

- PLATFORM-02: macOS/Linux platform stubs deferred to v2 (not blocking v1 release)
