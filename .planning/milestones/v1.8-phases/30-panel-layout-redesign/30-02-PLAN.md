## Goal

Expand the Plan 30-01 tracer into robust multi-monitor behavior: retain its production 16:9 shell, then make drag and resize offsets honor the current monitor work area through the existing display enumeration seam. This plan delivers the multi-monitor expansion portion of **LAYOUT-04** specified by the committed outline, implementing D-03, D-05, and D-06 without revisiting the Plan 30-01 geometry or tab-order work.

Purpose: prevent an already-open settings panel from straddling a secondary-display bezel gap while preserving a deterministic, usable fallback in headless and FFI-failure environments.

Output: tested work-area drag clamp, drag-session window-position cache, resize re-clamp, and fallback diagnostics in the settings overlay shell.

## Goal-Backward Check

### Observable truths

- A user dragging the overlay on a non-primary display cannot place any panel edge beyond that display's usable work area (D-03).
- A user can still drag in headless, missing-window, or recoverable FFI-error conditions because the established centered clamp remains available (D-03).
- A user resizing the player never leaves a previously displaced overlay outside newly legal bounds (D-05).
- Rendering isolation remains in place while the clamp logic changes (D-06).

### Reachability

- Title-bar `onPanStart` and `onPanUpdate` form the user entry path to the cached position and per-frame display query.
- The injected DisplayEnumerator and position reader make work-area and error paths reachable in widget tests without physical second-monitor hardware.
- `didChangeDependencies` observes MediaQuery size changes and schedules the same clamp path after layout has current panel dimensions.
- The existing `SettingsPanelController.state.dragOffset` is the single writable state consumed by `Transform.translate`, so every clamp becomes visible to the user.
