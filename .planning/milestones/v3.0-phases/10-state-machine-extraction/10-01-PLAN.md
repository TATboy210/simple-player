创建 `lib/kernel/engine/engine_state_machine.dart`:

EngineStateMachine 类，per D-02/D-03/D-05:
- 拥有3个 ValueNotifier: `ValueNotifier<MediaState> state` (初始 idle),
  `ValueNotifier<bool> isSeeking` (初始 false), `ValueNotifier<bool> isBuffering` (初始 false)
- 构造函数接收 `VoidCallback? onPlay` 和 `VoidCallback? onPause`（per D-09,
  togglePlayPause 依赖状态判断调 play 还是 pause，通过回调注入而非持有引擎引用）
- `bool transitionTo(MediaState next, String caller)` 方法:
  - 读取当前 state.value
  - 调用 `_canTransitionTo(current, next)` 检查合法性
  - 非法时: assert 内 debugPrint 警告 (per D-03), release 模式 return false
  - 合法时: state.value = next, return true
- `static bool _canTransitionTo(MediaState current, MediaState next)` 方法:
  switch expression 穷举6状态 (per D-01/D-04):
    - idle -> opening, error
    - opening -> idle, playing, error
    - playing -> paused, completed, error, idle
    - paused -> playing, error, idle
    - completed -> opening, error, idle
    - error -> opening, idle
- `void togglePlayPause()` 方法 (per D-09):
  - 读取 state.value
  - playing -> 调用 onPause 回调
  - idle/paused/completed -> 调用 onPlay 回调
  - error -> 无操作
- `void dispose()` 方法: dispose 所有3个 ValueNotifier

关键约束:
- 不导入 fvp_engine.dart（通过回调注入解耦，避免循环依赖）
- switch expression 必须覆盖 MediaState 所有6个值（编译期穷举保证）
- kDebugMode 来自 package:flutter/foundation.dart

创建 `lib/kernel/engine/playback_skip_mixin.dart`:

PlaybackSkipMixin mixin (per D-10):
- `mixin PlaybackSkipMixin implements PlaybackControl`
- 定义2个 abstract getter（mixin 自身需要但 PlaybackControl 不提供的依赖）:
  - `ValueNotifier<int> get position`
  - `ValueNotifier<int> get duration`
- 提供3个方法的 default 实现:
  - `void skipForward([int ms = EngineConstants.defaultSkipMs])`:
    `seekTo((position.value + ms).clamp(0, duration.value))`
  - `void skipBack([int ms = EngineConstants.defaultSkipMs])`:
    `seekTo((position.value - ms).clamp(0, duration.value))`
  - `void setRange({required int from, int to = -1})`:
    交换 from/to 如果 from > to, clamp 到 [0, duration], 调用 `_player.setRange(from: from, to: to)`
    注意: setRange 需要 PlayerProxy — 在 mixin 中声明 abstract getter
    `PlayerProxy get player` 或改为保留 setRange 在 FvpEngine
- import engine_constants.dart 和 playback_control.dart

注意 D-10 中 setRange 的归属问题（Research Open Question #3）:
setRange 需要访问 _player.setRange，mixin 无法直接访问。
方案: mixin 中声明 `void setRange({required int from, int to = -1})` 的默认实现只做参数校验和 clamp，
实际 _player.setRange 调用保留在 FvpEngine 的 override 中。
或者: setRange 完全保留在 FvpEngine（它需要 _guardedAction + _player）。

最终决定: setRange 保留在 FvpEngine（需要 _guardedAction + _player），
PlaybackSkipMixin 只提供 skipForward/skipBack 的 default 实现。
