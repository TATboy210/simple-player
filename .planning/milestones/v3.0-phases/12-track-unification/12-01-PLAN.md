### 发现的缺口

**UI 层没有调用 recordAudioTrack/recordSubtitleTrack/recordSubtitleDelay。**

| UI 操作 | 当前代码 | 缺失 |
|---------|---------|------|
| AudioTab 切换音轨 | `engine.switchAudioTrack(i)` | ❌ 未调用 `recordAudioTrack(i)` |
| 键盘 S 切换字幕 | `engine.toggleSubtitle()` | ❌ 未录制字幕开关状态 |
| 键盘 [ ] 字幕延迟 | `engine.setSubtitleDelay(delay ± 500)` | ❌ 未调用 `recordSubtitleDelay()` |

**后果：** 偏好只在 load→restore 链路工作，用户手动切换的轨道选择不会被记住。

## 实现计划

### Step 1: UI 层接入偏好录制

需要让 UI 层能够访问 `TrackPreferenceService`。当前 PlaybackController 持有该服务，但 UI 层只通过 `MediaEngine` 访问引擎。

**方案：** 将 `TrackPreferenceService` 通过 `PlaybackController` 暴露给 UI。

#### 1a. AudioTab — 音轨切换录制

```
AudioTab 当前: engine.switchAudioTrack(i)
AudioTab 修改: engine.switchAudioTrack(i) + controller.trackPreferenceService?.recordAudioTrack(i)
```

需要给 AudioTab 传入 `PlaybackController`（或回调）。

#### 1b. PlayerScreen — 字幕操作录制

```
键盘 S toggleSubtitle: engine.toggleSubtitle() + 录制新状态
键盘 [ ] subtitleDelay: engine.setSubtitleDelay(delay ± 500) + recordSubtitleDelay(delay ± 500)
```

### Step 2: 关于"合并为统一 MediaControl 接口"

Phase 12 成功标准 #1 说 "TrackManager + SubtitleConfigurator + VideoEffectController 合并为统一 MediaControl 接口"。

**评估：** 这实际上是 **已完成** 的。`MediaEngine` 已经组合了 `TrackControl + SubtitleConfig + VideoEffectControl`。三个实现类（TrackManager/SubtitleConfigurator/VideoEffectController）是 FvpEngine 内部的实现细节，不需要对外暴露或合并。

将它们合并为一个类反而违反 SRP — 音轨管理、字幕配置、视频效果是三个独立关注点。

**建议：** 标准 #1 重新定义为 "所有轨道控制通过 MediaEngine 统一接口访问"（已满足）。
