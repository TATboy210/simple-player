## What Was Done

3 edits across 2 files, fixing fullscreen gap + exit-to-top-left + window size desync:

### 1. `lib/kernel/bridge/win32/win32_platform_fullscreen.dart`

- **Added** `_swpNoActivate = 0x0010` constant
- **`enter()`**: Added `SWP_NOACTIVATE` to `SetWindowPos` flags (reduces unnecessary focus change)
- **`exit()`**: **Reversed operation order** — now restores style FIRST, then position/size. Added `SWP_FRAMECHANGED` to force `WM_NCCALCSIZE` frame recalculation. This is the primary fix for the gap issue.

### 2. `lib/kernel/bridge/fullscreen_controller.dart`

- **Added** `state.windowSize.value = _savedSize!` after `_platform.exit()` in the `setFullscreen(false)` branch. Ensures UI gets correct window dimensions after exiting fullscreen.

## Root Cause Analysis

| Bug | Root Cause | Fix |
|-----|-----------|-----|
| Fullscreen gap (缝隙) | `exit()` did `SetWindowPos` then `SetWindowLongPtr` — Windows calculated layout with fullscreen style, then style change shifted the window | Reversed order: style first, then position. Added `SWP_FRAMECHANGED` |
| Exit stuck at top-left | After exiting fullscreen, `_state.windowSize` was stale (still fullscreen size). Next resize debounce read wrong dimensions | Explicit `state.windowSize.value = _savedSize!` sync |
| Frame jitter | No `SWP_FRAMECHANGED` after style change — Windows didn't recalculate frame area | Added flag to both `enter()` and `exit()` |
